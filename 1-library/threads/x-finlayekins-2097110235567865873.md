## Summary

A listicle of seven practitioner heuristics the author attributes to a coffee conversation with Geoff Huntley (secondhand, not Huntley's own words). The ones that touch our topics: control LLMs with deterministic gates that fail loudly rather than with prompts; advertised context windows overstate usable context (he cites NVIDIA's RULER benchmark as putting effective context at 50 to 65% of advertised, number not checked by us); sub-agents are "garbage collection" for context, run the 100k-token job in a disposable stack, write the result to a file, and pass back a reference rather than the content; compaction summaries degrade quickly, so minimise allocations with sub-agents, skills and handoff files instead. The rest is about reading model cards and not reading code. Opinion and folklore; no measurements of its own, and the closing "RSI 2027, we already have AGI" line signals the register. Catalogued because the "sub-agent returns a reference, not content" pattern is a practitioner answer to the fork-merge reintegration problem: the parent never ingests the child's raw context.

**1. @finlayekins, 2026-09-07 23:50 UTC, 30 likes** (status 2097110235567865873)

Got coffee with @GeoffHuntley (Mr Ralph Loop). The 7 AI engineering principles that stuck:
 
1. "The agents are drunk and high" 

Prompt engineering is astrology for men. The only way to control LLMs is to encode your rules as deterministic gates that fail loudly (back pressure). Use "friendly prompt injection" - A pre-commit hook that runs your tests and echoes the failures.

2. "Context windows are a lie" 

Stated at 200k tokens means ~176k usable, and every MCP server you install eats it at session start. People install the top ten from Reddit, work with a 16k context window, then complain Claude Code is bad. (NVIDIA's RULER benchmark puts real effective context at 50-65% of the advertised number.)  

3. Skills exist to fix the problem

The best analogy for LLMs is a section of computer memory, which is finite and gets filled with junk.  Skills act as just-in-time memory paging: load the instructions when you need them, not at boot.  

4. A sub-agent is the garbage collection evolution.

Subagents fix agent memory in the same way garbage collection software language like Java fixed the memory issues of C. You run the 100k-token test output in a disposable stack, write it to a file, message back the reference. You've rebuilt an OS scheduler, and saved your main session memory

5. Compaction degrades rapidly

Instead of relying on constantly worse summaries, minimise memory allocations in the first place - use subagents, skills, and handoff files.

6. READ THE MODEL CARD 

Every Frontier Lab LLM ships with a 200+ page PDF describing how it was trained and should be used. No one reads this. Without it, your skills detune rapidly between models, and people complain 'Fable sucks'.

7. Stop reading the code

LLM writes the deterministic test suite, the hooks enforce it, and that is the code review.  Spend the time understanding fundamentally how the models work instead. "This is your one time in life to develop the theory of mind". RSI 2027, we already have AGI.
