## Summary

Sarkar characterizes Cloudflare pay-per-crawl as commerce through HTTP 402, signed Web Bot Auth requests and Stripe, rather than a new anti-scraping defense. He then promotes DeepScrape deterministic selector reuse and repair as a separate token-cost optimization. The described access protocol and efficiency benefits are unverified claims, not measured results in the thread.

## Archived text

Cloudflare's pay-per-crawl isn't a new anti-scraping weapon, according to the team at ScrapingAnt. It's a payment rail: a site returns a 402, a verified crawler signs its request with Web Bot Auth, and Stripe settles the payment. That's commerce, not defense, and it means a chunk of the web is quietly splitting into two economies: licensed and metered on one side, the open long tail on the other, with anti bot systems caught in between that still can't tell a legitimate agent from a bad bot.

Here's what stands out to me: that access layer is only half the problem. Getting past the gate, paid or not, doesn't make extraction cheap. Most agent pipelines still burn tokens asking a model to guess a CSS selector, then burn more tokens again next week when the page changes and the guess goes stale. That's the actual cost center hiding behind every scraping bill, separate from whatever a site charges at the door.

DeepScrape treats that as the real problem to solve. Selectors get generated once with an LLM, then reused deterministically and self heal when a page's structure changes, so the model only gets called again when something actually breaks, not on every single pass. The MCP server exposes those scrapers directly as tools inside Claude or Cursor, and Site to MCP turns any website into a structured source an agent can query on its own. Pay for access where a rail exists. Don't keep paying a model to re-read the same page a thousand times after that.
