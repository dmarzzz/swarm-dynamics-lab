## Summary

Sidhu interprets Cloudflare crawler blocking and pay-per-crawl as a shift from exclusion toward metered access. He distinguishes self-reported user-agent strings from signed cryptographic verification and argues that billable traffic has an incentive to identify itself. This is an opinion about infrastructure incentives, without measurements of deployment coverage or actual bypass success.

## Archived text

Cloudflare no longer sells keeping bots out. It sells charging them.

That is the whole answer and it happened in the open. In 2025 Cloudflare began blocking AI crawlers by default and launched pay-per-crawl, letting publishers set a price for each request from an AI company rather than simply refusing it.

Blocking was the old product. The current product is a toll booth.

Which is why declared AI user agents get through where anonymous scrapers do not. A crawler that identifies itself can be metered, billed and attributed.

One that hides cannot.

Honest identification became the fast lane specifically because it is the billable lane.

Spoofing a user agent to get through is trivial and it always has been, because user agent is a self-reported string with no verification. That is a known weakness and it is why the serious version of this uses signed requests and cryptographic bot verification instead.

The mitigation exists. Most sites have not turned it on.

The irony in the post is real and it is pointed at the wrong layer. A network that started as a shield now sits between publishers and the companies training on them, taking a position in the middle of both.

Every infrastructure company eventually discovers that the toll is worth more than the wall.

The bots got in because somebody found a way to invoice them.
