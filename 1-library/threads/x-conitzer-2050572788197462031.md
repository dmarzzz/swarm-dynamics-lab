## Relevance to us

This bears directly on our k-of-n merge question: [[liu-2026-consensus]] reports a token-level combination rule that tolerates a corrupted majority, where plain voting (the usual Byzantine-threshold intuition, see [[guerraoui-2024-byzantine]]) fails. If a parent agent merges outputs from forked parts token by token, this is a candidate merge rule that does not require an honest majority. The "no clear unit entity" framing in tweet 2 also fits the fork-and-merge view of agent identity.
