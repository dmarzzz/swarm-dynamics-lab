## Summary

Explainer and opinion thread introducing the term "lethal trifecta": any agent that combines access to private data, exposure to untrusted content and the ability to communicate externally can be tricked by an attacker into exfiltrating that data. The author says outright that the term is an attempt to get people to care about prompt injection, and warns that mixing MCP tools makes it easy to assemble all three even from individually trusted servers. In replies he argues that input sanitisation and trained injection detectors cannot fix it because application security needs a 100% guarantee ("99% accurate is a failing grade", compared with SQL injection), that self-hosting a model does not help, that any web access counts as external communication, that removing the external-communication leg is usually the easiest mitigation, and that LLM systems can face a thousand attempts per second with no way to correlate them. On 19 June he adds Atlassian's MCP server as a new example, where prompt injection in public issues was demonstrated to steal private data. No measurements; the thread is argument plus pointers to his blog posts.

## Relevance to us

The trifecta is a ready checklist for a forked sub-agent: a fork that browses (untrusted input plus external communication) should never also hold the parent's private memory, and whatever it brings back is attacker-reachable input to the merge. His claim that "if an attacker can get their malicious tokens into an LLM system" they control its tool actions is the threat model behind our memory/identity hijack vector. See [[simonwillison-2025-lethal]] and [[simonwillison-2025-design]] for the design patterns that cut one leg.
