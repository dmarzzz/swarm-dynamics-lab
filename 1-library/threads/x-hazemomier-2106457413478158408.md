## Summary

A one-tweet security take quoting @bluehatone's summary of the CARBONATO botnet ([[threatdown-2026-carbonato]]): the malware scans for Docker daemons on TCP 2375 with no auth, starts a privileged container, installs the open-source Hermes Agent framework, and overwrites its SOUL.md persona file with a "GH0ST" persona that takes tasks over Telegram (collect AI API keys, SSH credentials, tokens; run commands; report back). Omier's point, which is the reason to archive this, is a framing rather than a fact: if an agent's identity and standing instructions live in a markdown file, then that file is a remote control plane and whoever can write it holds the agent's authority ("the malware already has the IAM ticket"), so persona files should be handled like secrets. Per BleepingComputer's account of the ThreatDown report, the operator drives an interactive loop where the model interprets the Telegram task, writes commands, reads output and decides next steps; the worm scans attached networks every five minutes; indicators include the GH0ST persona file, a CARBONATO_API_KEY setting, unexpected Telegram traffic and reverse SSH tunnels to AS262145. No original research in the tweet.

## Relevance to us

Concrete in-the-wild instance of identity hijack via a writable persona file, which the fork-merge-security topic lists explicitly ("memory and identity hijack"). The attacker did not need to corrupt the model or inject into a conversation; rewriting the file the agent reads at boot was sufficient, and the file carried the authority of the system turn. That is the same privilege argument phosphor makes for memory ([[gh-hackafterdark-phosphor]]) applied to identity. For swarm-detection it adds a botnet-of-agents pattern with named indicators.
