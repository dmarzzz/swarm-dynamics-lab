# Changes needed before native execution

The case builder, literal reference, scorer, treatment checks and fixture preview are implemented. This file specifies the remaining native integration; it is not an executable launch instruction or an approval receipt. Preserve the completed RD5 runtime and results.

| Component | Required change | Acceptance evidence before launch |
| --- | --- | --- |
| Admission and proposal binding | Create a separate RD6 entry point tied to the approved plan, exact assignments, source dependencies, latest private closeout and new diagnostic assessment. Keep the historical H5 `complete_valid_result` record unchanged. | Missing approval, altered plan/source/manifest, stale account/claim/public-plan evidence and unavailable supported snapshot all reject without dispatch. The public sanitized parent summary is not a substitute for the private operations journal. |
| Original budget ledger | Use the existing single-writer ledger; add explicit RD6 Q0/D0 limits of 18/144 only after a real scope/call-ceiling decision. Retain every old call, reservation and RD5 fence. | Empty/copied-reset ledger rejected; lifetime stop 650 only when authorized; USD 1 API and USD 1 infrastructure retained. Reserve before dispatch; an ambiguous response remains charged at its reservation. |
| Assignment and repeat identity | Key dispatch by stage plus assignment, retaining canonical and ordered request hashes. Two repeats intentionally share request bytes but must have distinct call identities. | A duplicate assignment cannot run twice; a second approved repeat is not incorrectly served from a hash cache. No provider response is reused between conditions or repeats. |
| Exact request delivery | Preserve the planned question/criteria ordering, provider restriction, task fields, source/card agreement and clock masks. Fresh request state every time. | Read actual delivered body bytes back against the frozen ordered-request digest, with no undeclared field, truncation, conversation history or fallback. A semantic model/schema change gets a new plan and qualification. |
| Qualification transition | Reconcile 18 Q0 slots and inspect every response before admitting D0. D0 includes its own interleaved C00 comparisons. | Any Q0 wrong, invalid, missing or unstarted response prevents D0. A passing Q0 does not certify full-context decisive competence or authorize another stage. |
| Failure and lifecycle handling | Append assignment/request, dispatch, visible response and terminal events; stop on ambiguous dispatch or invalid route/schema. Supervise worker and local relay together. | Inject pre-dispatch disconnect, post-dispatch unknown result, duplicate start, expired lease and artifact-upload failure. Every assigned slot remains visible; no automatic retry, refund or resume. |
| Scoring and reporting | Feed validated visible actions into the offline scorer; add provider-provenance checks rather than changing the scorer's `native_evidence: false` into an unsupported claim. | Independent action/label arithmetic agrees; duplicate/unknown/bad-hash rows reject; missing cells remain unknown. Inspect all native misses and repeated disagreements. |
| Measured visualization | Replace the expected-only viewer with an observed two-repeat grid and chronological dispatch/cost strip; retain exact input links and status colors. | Initial, transition, failure and final views match saved events. Expected labels remain outside the actor request. Browser layout must be inspected before calling a native visualization verified. |
| Closeout | Use the shared offline finalize hook for each stopped attempt, then complete the owning scientific assessment against all eleven dimensions. | Native readback and budget reconciliation complete; process and scientific outcomes distinct; workers stopped and allocation released. No automatic successor. |

No native adapter is claimed for this draft. Shared `prepare`/`check-update` commands currently support other implemented adapters; this study's future manual runner must enforce equivalent bindings. The generic `next-run-plan.json` is a review artifact until its actual execution contract and predecessor are bound. A passing case suite is not evidence that these launch-path checks exist.

The synthetic clock is model input, not an observed physical deadline. This diagnostic scores the immediate interpretation of a delivered packet. API latency is recorded separately; a later end-to-end recovery study would need real acquisition/scheduling and deadline endpoints.
