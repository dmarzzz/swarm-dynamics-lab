# The Right Dissenter live exploratory study

Design RD-2, written 2026-10-04 before native implementation. This amendment operationalizes RD-1 as a standalone experiment, `right-dissenter`, in the decision-models and dissent areas. The owner explicitly requested deployment and execution. It authorizes an exploratory competence test and development comparison in owned notes; it does not mark the unfinished survey or independent review as passed. Confirmatory seeds remain unopened.

## TLDR

Can a minority earn a useful independent check without giving every objection a veto? Jev selects whether to check and then interprets the observation in three simulated scenarios: a bridge inspection, a build release and an alarm that later becomes true. Compare majority, blind veto, always-check, a fixed random check allocation, pooled evidence and an exact grammar reference. Measure correct on-time decisions, corrections, harmful reversals, checks, withdrawal and reopening over every assigned opportunity. This is a small synthetic mechanism study with scripted initial votes, not evidence of spontaneous collective intelligence or real operational safety.

## Question and prediction

A useful dissenter must be accountable to evidence: state a falsifiable objection, accept a bounded test, withdraw after disconfirmation, and be heard again when genuinely new evidence arrives. The useful outcome is fewer wrong commitments at an acceptable cost, not more disagreement. Jev may add no benefit over a transparent deterministic rule or checking every eligible challenge.

RD-2 adds **content agrees**: the challenger demands reversal even though its cited report supports the existing action. Scope and freshness checks cannot catch this semantic inconsistency. Admission should save a check here. A plausible but wrong observation remains worth checking; no policy is expected to infer hidden sensor truth from identical inputs.

## Setup

The RD-1 state machine, actor whitelist, three scenarios and logical deadlines remain unchanged. All actions are simulated. Four majority records share one ancestor; one challenger has a separate ancestor. This topology is fixed and disclosed. PROCEED/HOLD are balanced. Private clean decisions qualify Jev first, but the policy comparison uses scripted votes, explicitly recorded as such. Natural minority formation is future work.

Native route: OpenRouter decisions endpoint, requested `typesafe/jev-1.13`, TypeSafe only, no fallback; expected served snapshot `typesafe/jev-1.13-20260917`. Fresh official metadata must agree before launch. Observed published rate on 2026-10-04 is $0.042 per million input tokens and no output charge; reserve 32,000 tokens per call ($0.001344), refuse higher pricing or an unknown snapshot. Credential remains in the protected local store and is consumed by a loopback relay. The dedicated remote worker receives no API key.

## Protocol

1. Publish this immutable plan, source and pre-run assessment. Register the experiment and run TLDR publicly; verify through the public-plan preflight before any qualification or development dispatch.
2. Obtain an exclusive `sim-right-dissenter` allocation owned by vishesh. Deploy the frozen source, run offline checks there and verify the merged claim immediately before launch.
3. **Q0:** 18 clean decisions, six per scenario, balanced three PROCEED/three HOLD. Seeds 2100–2117, allocated consecutively by scenario. Each packet contains one current, scope-matching observation, no votes/challenge; admission is not involved. The independent check grammar supplies the observation. Grade exact action after strict route/schema validation. Require at least 17/18 valid, 16/18 correct, and 5/6 correct per scenario. Failure blocks S1. Preserve the failure and write a post-mortem before any bounded repair diagnostic with new cases.
4. **S1:** 52 root cases: bridge/build × both truth labels × both majority labels × {standard, content_agrees, wrong_scope, noisy_check} = 32; bridge/build × both truth labels with wrong majority × {stale,no_check,late,absent} = 16; four alarm trajectories (two per direction) = 4. Seeds 1110–1157 for the static rows in that order, alarm seeds 1180–1183. Temporal trajectories each contain disconfirmation, an unchanged repeat and a fresh observation after world change.
5. Each case receives all seven RD-1 policies. Arm order rotates by case index, fixed before responses. The random arm checks even-indexed cases only (26/52 assigned roots); this is a **fixed 50% allocation**, not a claim to match the realized evidence-gate cost. Report its true expenditure. Exact-reference always uses the deterministic parser, never Jev. Pooled sees the same original union; checks acquire additional information whose cost is reported.
6. Identical Jev requests within an attempt share a saved response, including failed responses, across policies. This deliberately holds adjudication constant for equal acquired information, avoids accidental retries, and means policy estimates are paired counterfactuals, not independent model samples. Retain cache hits and both actual paid and per-policy logical call counts. No cache across Q0 and S1.
7. Native transport accepts only hashes of frozen possible actor requests, generated before dispatch by enumerating allowed admission/resolution actions. Gold never enters request construction. A transaction reserves worst-case spend before each unique request. Failed or uncertain calls keep their reservation; no retries. Schema-valid wrong answers are results.
8. Every assignment is written before dispatch. Record requests, validated response metadata, sanitized fixed error codes, events and elapsed time incrementally. Missing assignments remain in the denominator. Stop on exhausted cap, route/price mismatch, five consecutive transport errors or wall-time limit. A stopped attempt remains an incomplete result; never quietly continue in an overwritten directory.

## Metrics

Q0 reports valid and correct counts out of 18, by scenario and action label. S1 has 60 decision opportunities per policy (48 static plus 12 alarm) and 420 across seven policies. Primary is correct-on-time / all assigned opportunities, with paired differences against majority and always-check. Secondary: correction/wrong-majority denominator, harmful reversal/right-majority denominator, wrong PROCEED, unnecessary HOLD, DEFER/failure/missing, checks, semantic-inconsistency rejection, temporal withdrawals/repeat suppression/reopening, paid calls/tokens/cost and wall latency.

Roots, not frames or policy rows, are units. This design has repeated grammar and a fixed topology; do not give seed variation the interpretation of semantic diversity. Report raw counts and paired descriptive differences; no broad population significance claim. Logical deadlines test protocol timing, not real-time API latency. Show the RD-1 illustrative harm weights only as sensitivity analysis, alongside raw outcomes.
