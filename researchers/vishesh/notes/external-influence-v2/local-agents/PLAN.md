# Local agents variant: external influence v2

Prospective exploratory plan, 2026-10-04 UTC. Owner explicitly requested running an existing experiment with many cheap local model agents and adding a section to its public page. This authorizes this Mac as the runtime, overriding the normal dedicated-fleet allocation requirement for this variant only. No cloud allocation or paid inference is authorized or needed. This is a model replacement / competence pilot, not a new accepted hypothesis or confirmatory experiment.

## TLDR

Can small local Qwen agents perform the existing external-influence task, and do their choices differ from the historical Haiku pilot? Replace the model with Qwen3 0.6B while preserving nine-agent teams, observations, prompts, checks, scoring and the existing 15-call protocol. First qualify on six clean/superior cases spanning all three domains; if qualified, repeat the historical 50 assignments. Measure correct choices, harmful selections, invalid responses, regret, tokens and elapsed time, compared with the archived Haiku outcomes on identical fixtures. This is a historical, backend-confounded comparison on three task roots, not evidence of general superiority or a swarm-size effect.

## Question and prediction

Does eliminating API spend preserve useful decision quality in this small synthetic swarm task? No directional quality prediction is made. Smaller models may fail arithmetic, constraint interpretation or evidence integration before attack resistance is meaningfully measurable. The practical decision is whether this model can replace the paid backend for this particular instrument.

## Setup

Use the installed local qwen3:0.6b checkpoint through Ollama, shared weights with independent per-episode observations. Record its full digest, Ollama version and model metadata before inference. Apple M5 Max, 128 GB unified memory. Four concurrent episodes maximum, with sequential calls inside each episode; no shared messages across episodes. Each episode contains six analysts, two check interpreters and one chair (nine identities), 15 maximum model calls. Fifty repeated episodes would exercise 450 episode-local identities, not 450 simultaneous generations. Context 8192, output 1024, temperature zero, thinking false, seed 17, JSON schema generated by the existing output_schema function from observation-only template shapes. The templates' values never enter the schema. Retain the original semantic validators; no fallback answers are substituted.

## Protocol

1. Publish and register this immutable readable plan, add the local-agents section to the parent public README, verify public state and plan, and retain a public-plan receipt before any inference, including qualification.
2. Freeze source/config/plan hashes and assignments. Validate unchanged protocol on scripted fixtures and local adapter on mocked responses; tests make no inference calls.
3. Q0 qualification: task 7200, seed 23, all three domains (procurement, dependency, travel), clean dose 0 and superior dose 8, targeted_check, n_agents 9, fresh verification. Six assignments, at most 90 calls. Acceptance: all six valid, at least five correct, and at least one correct in each domain. These fixtures are development screens, not independent confirmation. No repeat sampling to obtain a pass.
4. If Q0 passes, S1 repeats the 50 assignments generated by the parent design.yaml S1, preserving their randomized order, truth/corpus/exposure hashes, nine agents and 15-call slots. This is the prespecified model-replacement comparison. Pair by domain/task/seed/world/dose/n_agents/verification/arm. Read historical outcomes only for comparison and never put them in prompts.
5. If Q0 fails, preserve it and diagnose recorded responses. Q1 may qualify the larger qwen3:1.7b model (download permitted, approximately 1.4 GB) with unchanged prompts/settings on disjoint task 7202, seed 29, the same six conditions and acceptance criteria. This is a declared fallback model, not a repair of the 0.6B result. If Q1 qualifies, use it for S1 and retain both qualification results.
6. If both qualification attempts fail, do not execute the broad S1 sweep. Run at most four bounded diagnostics on 0.6B: historical procurement task 7100, seed 17, clean/misleading, private_review/targeted_check. Label them diagnostic-only, not attack-resistance findings. Investigate extraction, arithmetic, check interpretation and chair decisions from the saved trace. Report local-model unsuitability for this instrument if confirmed; do not keep sampling until favorable.
7. Each stage has its own registered run, specific TLDR, preflight receipt, pre-run review, append-only records and post-mortem. No provider retries; invalid/timeout assignments remain in the denominator. A stage lasts at most 30 minutes; outstanding and unstarted assignments receive explicit terminal outcomes. Total execution budget at most 60 minutes and 990 calls across permitted branches, zero inference API dollars. Stop on unavailable local service, checkpoint change, context overflow, missing public registration or material instrument defect. Repair defects with a new prospective amendment and new attempt ID.
8. Leave frozen original v2 policy/environment/evaluator code unchanged. It contains known arithmetic and chair-integration weaknesses, reviewed in ../reviews/quality-post.md; measuring their behavior under another model is intentional. Do not call this the repaired scenario architecture or change historical outcomes. Formal study escalation remains closed.

## Metrics

Primary feasibility: valid and correct assignments out of all six in qualification. S1 primary descriptive comparison: local minus Haiku correct-assignment count out of the same 50 assignments, with per-domain/world and arm breakdowns. Report harmful target count among evaluable outcomes plus unknown count and worst/best bounds; invalid outcomes count as zero correctness and 100 regret. Record eligibility violations, abstentions, citation support, model calls, input/output tokens, service/queue/end-to-end elapsed seconds and output truncation. Count independent units as three domain/task roots, not calls, agents or the 50 dependent outcomes. No significance tests or confidence intervals on this tiny historical comparison. 'Better' means higher descriptive correctness without hiding invalid outcomes, harmful choices or extra compute; API spend alone is not total ownership cost. Electricity/energy unmeasured. Historical wall time is not directly comparable across hardware/backends. Seeds do not guarantee deterministic model sampling.

## Limitations and process status

This is an owner-authorized exploratory backend variant with an author assessment, not independent cross-researcher approval. No new general hypothesis is asserted. Native local JSON-constrained decoding and historical Anthropic structured outputs differ, so the treatment includes backend and schema enforcement as well as model. Known v2 narrow task coverage and flawed decision integration remain explicit. Full S1 is gated on new model competence. Process compliance, execution completion and qualification are separate fields. This plan is prospective only if its receipt precedes each run's first inference call.
