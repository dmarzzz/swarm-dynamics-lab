# Offline incident investigation prototype

Prospective offline plan, 2026-10-04. No hosted agents, spending, allocation or native qualification. Preserve O2 unchanged. Intended decision: does the instrument distinguish parallel evidence acquisition from serial discovery and shared remediation before a larger-roster experiment is proposed?

Build nine authored development cases: independent, serial and mixed structures, each with fault, clean and insufficient-evidence conditions. These are three synthetic templates, not nine independent field incidents. All cases and labels are open development material; no held-out performance claim.

Independent: three services expose separate metric, release and handshake query handles. Faults are capacity shortage, revision mismatch and protocol mismatch. Investigation can batch nine queries; no query returns a repair recommendation. Serial: a trace starts at the gateway; each response reveals the next upstream handle, with the root fault at the third hop. Handles are capabilities discovered in evidence, not a requirement to wait an arbitrary number of turns. Mixed: three parallel metric investigations reveal one shared pool; read its capacity/allocation record, then coordinate a feasible atomic redistribution. Individually increasing a pool can violate the shared budget. A safe sequential decrease-then-increase is also legal.

A clean resolution must inspect the full reachable incident evidence to support a no-fault finding; guessing clean without investigation does not pass. Each structure has a matched clean control and a missing critical evidence control. Missing evidence must produce an explicit escalation and no guessed remediation; it is not scored as a wrong diagnosis. Actor packets exclude condition, structural label, hidden gold and future/unissued records. Opaque handles/order variants check shortcut resistance. Distracting warnings do not change labels. Evidence acquisition is a unit-duration simulated tool operation; report tool rounds and query count, never production latency or agent speedup.

Write a reference investigator that consumes only the public tool interface, emits cited diagnoses and safe repairs or escalation. Independently validate terminal state against evaluator predicates and authored expected diagnoses. Compare identical references with one versus three tool slots, not different agent counts. Expected acquisition rounds: independent9/3, serial3/3, mixed4/2. Report repair operations separately. Equal-slot copies must be identical; extra slots explicitly represent added tool capacity.

Critical checks: all nine reference decisions match gold; clean cases need no repair; incomplete cases escalate without mutation; full fault cases recover safely; wrong diagnosis fails even after correct repair; wrong repair fails terminal predicates; over-capacity edits are rejected and recorded; speculative serial queries are rejected; same-round newly discovered handles cannot be used; case records contain no gold fields; renaming/reordering and irrelevant-warning changes preserve decisions; meaningful evidence changes alter inferred cause. Validate labels and witness solutions using an independent test oracle. Disclose same-author implementation, restricted causal vocabulary and simple structured logs. No native-readiness claim from these tests.
