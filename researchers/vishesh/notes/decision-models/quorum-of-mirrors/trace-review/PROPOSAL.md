# Revised proposal: earned headroom before a semantic resolver run

**Decision now: no native dispatch.** The 24 authored development bundles do not demonstrate an unmet decision after a modest deterministic controller. This proposal defines what would justify a bounded next run; it is not an approved or ready native packet. The prior D1/M1/C1 arithmetic progression stays parked after reassessment, not by assumption.

## Empirical question and practical decision

Can a native resolver identify which authenticated acquisition receipt supports a natural-language report, adding useful correctly resolved coverage beyond exact lookup, normalized text, lexical matching and a fixed synonym controller, without admitting wrong or dependent sources as new evidence? The downstream dependence check and exact arithmetic are shared code in every arm. Models do not decide that matching text means an independent acquisition.

If useful coverage improves by at least four of 24 evaluation bundles with zero incorrect receipt admissions and zero false new-dependency-group admissions, consider a separately scoped integration pilot. Null/adverse results retain lookup plus abstention. Inconclusive/qualification/transport failure retains the unresolved claim and stops; no automatic repair or larger sample. Missing authoritative evidence always requires abstention or retrieval, never voting among guesses.

## Development evidence and readiness gate

The completed 24-bundle development set covers six cases in each of four families: paraphrased copies, identical wording from different acquisitions, missing receipts, and common-cause dependence. These are authored templates with known construction labels, not an independently adjudicated natural corpus. Exact reference lookup resolves 6/15 resolvable cases; normalized text resolves 9/15; lexical matching 8/15. The small fixed-synonym hybrid resolves 15/15 and abstains correctly on nine unavailable/ambiguous cases. All four controllers make zero incorrect admissions on these fixtures; common-cause mapping is not confused with new-group admission.

The hybrid dictionary was written using these six wording templates. Its perfect development fit does not establish broader accuracy. Conversely, weaker baseline misses are not evidence that a model is necessary when the stronger baseline already resolves them.

Before proposing actual dispatch: collect 24 additional development bundles from varied consented/public acquisition records or clearly labelled independently constructed synthetic events, verify target mappings from authoritative receipts, establish that at least four resolvable cases defeat the frozen hybrid for meaningful semantic reasons, and show that those cases remain identifiable from the available evidence. Reject artificial difficulty introduced by withholding indispensable provenance or changing only aliases. Record the exact corpus source and rights; owner/operator prompts and private traces are excluded. No researcher sign-off is reintroduced; adjudication and evidence audit are substantive dataset work by the owner of the study.

This readiness gate is **not met**. No new corpus is claimed to exist. Do not generate sealed evaluation data merely to manufacture headroom on a solved template.

## Conditional bounded run construction

If development establishes a decision-changing gap, prepare exactly two named stages under a new semantic instrument:

- **SEM-Q0-01:** eight clean qualification bundles, two per family. Require 8/8 structurally valid, >=7/8 exact mapping or required abstention, all missing/ambiguous cases correctly abstained, and no incorrect receipt/new-group admissions. Qualification is instrument capability, not evidence of general efficacy.
- **SEM-S1-01, conditional:** 24 newly collected and sealed bundles, six per family, disjoint acquisition/event families from development and qualification. One native call per bundle, no repeats/retries. The same input is scored by the frozen deterministic controls without model calls. Explicit receipt references, available receipt candidates, event metadata and known dependency groups are matched across policies. Candidate order is balanced and frozen before dispatch. Report byte lengths and cost; these controls are not equal-compute treatments.

Use one pinned stateless resolver configuration, no provider/model fallback, tools, conversational peers, prior choices or operator context. Fresh predeclared output: an enumerated receipt ID or DEFER, never a claimed independence score. The old ZERO/ONE validator is not reused to mis-score receipt IDs. The model/endpoint must be explicitly requalified for this contract; this document does not claim the adapter exists or that historical reader qualification transfers. Extra working/rationale fields would change the instrument and need prospective justification; they are not fabricated from old traces.

The 24 evaluation acquisition/event families are the intended task units; six per stratum gives coarse finite-support sensitivity. A single case moves the endpoint by 4.17 percentage points; a useful gain requires four cases. This is a feasibility screen, not a production safety guarantee. Even zero errors in 24 iid cases would allow an approximately 11.7% one-sided 95% upper error bound; actual event sampling may not justify iid inference at all. Report paired case-level differences and exact denominators; do not turn development templates, copied reports or optional repeats into independent n.

Scorer and baseline hashes remain fixed.

Stop at the first provider/schema/accounting or live-admission failure, failed clean qualification, session deadline or cap. A valid negative run completes the scientific cycle. No changing wording, threshold or baseline after evaluation starts, no automatic second model or repair.
