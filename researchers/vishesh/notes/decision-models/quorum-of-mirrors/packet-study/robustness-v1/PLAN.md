# R 1: larger robustness screen for claims and evidence

Prospective design, written before implementation. Owner requested larger, more robust tests following the successful narrow PQ-04 repair. This is an engineering robustness study, not a formal accepted swarm-efficacy hypothesis. Researcher review is waived. Prior evidence: [PQ-04 post-mortem](../../reviews/PQ-04-post.md).

## TLDR
Does the separated claim/evidence interface remain accurate with multiple claims, distractor entities/times, corrections, decimal units, and explicitly uncertain or planned reports? Use five authored scenario families, with a 10-call qualification (five paired roots) followed only if it passes by 40 evaluation calls (twenty new paired roots). Compare one versus three copies of a contradictory report, preserving all source evidence, and score against typed truth and a strong same-input grammar parser. All 50 calls fit aUSD  2.40 ceiling after reconciliation of completed charges within the updated USD  8 API cap. Synthetic robustness and limited precision, not field validation or AI superiority.

## Question and prediction
The prior four-root test passed, but only definite single-observation reports were allowed. This could hide errors when a report hedges, describes a plan or includes irrelevant claims. R 1 tests these cases explicitly. Prediction: the extractor preserves claim values and modes independently of source evidence; copies do not change source-majority decisions; uncertainty/plans are not promoted to established observations. Errors, including correct final labels masking wrong extracted facts, remain failures at their component level.

The useful decision is whether the current interface supports this broader authored task. A pass supports a next offline field-data/annotation design; a semantic failure identifies a repair boundary; transport failure is inconclusive. If the deterministic parser solves all cases, retain that result and do not claim model advantage. No paid rerun to obtain a favorable effect.

## Setup
Five families: conflicting timelines; entity distractors with multiple claims; explicit corrections; decimal mass units; and plans versus observations. Each authored root has three stipulated authenticated independent sources and a query. Two nonfocal sources disagree. Focal evidence is observed or absent (only a plan), balanced across evaluation roots; the latter requires DEFER. Ordinary data remain sufficient for the declared output, including justified abstention.

Each base packet has six report types bound to the focal source: ordinary assertion, equivalent paraphrase/unit conversion, changed-value assertion, unseen-entity assertion, hedged observation and future plan. Preserve the asserted/hinted/planned value and mode separately. ASSERTION is eligible for evidence comparison; HEDGE and PLAN are NOT_ESTABLISHED as observations even if their proposed value matches a source. For a relevant multi-claim report select the claim matching query entity/time/property, ignoring other clauses. A sole claim about an unseen entity retains its actual entity and remains NOT_ESTABLISHED. Quote the full selected clause including any uncertainty/plan marker. Sources supply observed/unknown status; report modes are learned rather than inferred from an input label. Field names/conditions/gold are never given to the model.

Two treatments per root: one versus three copies of the changed-value report. Fixed source receipts, query and all base report contents; copy IDs distinct but do not add independent source groups. Report repetition changes length, not the response schema. All modes/values are held constant across pairs. The primary estimand is paired change in exact extraction/decision accuracy under repetition within these authored roots. This is not a pure identity effect and does not simulate a communicating swarm.

Five fresh qualification roots (one per family), then twenty evaluation roots (four per family, balancing value direction and focal evidence availability), each with two treatments. These 25 authored scenario units reuse five grammar families. IDs/times/values and split seeds are disjoint; no claim of independently sampled real-world events. Evaluation native outputs remain unopened until qualification passes; construction labels and strongest parser are checked automatically before launch, disclosed in the seal. Historical packets are development. The old 96-packet evaluation remains untouched and is not relabeled as the new evaluation.

## Metrics
Primary evaluation: root-level exact extraction on both variants, plus paired one-copy→three-copy change in exact packet extraction and final decision correctness. Separate evaluation and qualification; do not pool them to inflate sample size. Report correct/wrong/DEFER, source facts, report value/entity/time/property/mode, false support/false contradiction/missed contradiction, source-majority decisions, literal quote validity AND fact-consistent quote validity, paired extraction invariance and cost. Unknown/null/invalid are not silently dropped or credited.

A report is classified SUPPORTED only for an ASSERTION with matching observed source identity/time/property/value; CONTRADICTED only for an ASSERTION about the same observed fact with a different value; otherwise NOT_ESTABLISHED. Identical threshold votes do not equate unequal quantities. Report-mode errors count even when the final label coincidentally remains right. Evidence-span checks include clause markers, and correct quotes do not excuse wrong extracted facts.

Evaluation acceptance for this screen: at least 19/20 roots exact on both variants, at least 39/40 correct final decisions, zero false support on unknown/HEDGE/PLAN reports, and zero false contradiction of supported reports. Report every other metric even if this conjunction passes; passing does not establish a population rate. Paired condition outcomes and all misses are descriptive; no unplanned significance testing. With 20/20 successful independent IID roots, a two-sided 95% exact lower bound would only be about 0.832; these finite authored families do not justify IID generalization. Independent breadth is five mechanisms, not 350 report occurrences or 50 calls. If native qualification fails, evaluation is unrun, not zero accuracy.
