# Evidence for representative agent workloads

This is a targeted primary-source check on 2026-10-03, not a survey of market share. It supports using research, code evaluation, tool-mediated workflows and policy-constrained service as recognizable task families. The proposed scenario sizes, rankings and swarm treatments are our design judgments. A benchmark task is evidence of an evaluation practice, not proof of widespread production deployment or a multi-agent advantage.

| Source freshly opened | What it establishes for this design | What it does not establish |
|---|---|---|
| [Anthropic multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system), June 2025; engineering account read | A production research workflow uses a lead agent, parallel searchers, synthesis and citation processing. The account discusses duplicate work, delegation and evaluation. | The proposed frozen curation task is not its internal benchmark. Its reported gains and token ratios do not predict ours or establish present market-wide prevalence. |
| [SWE-bench official site](https://www.swebench.com/); task descriptions read | Repository-issue resolution is an established coding evaluation task. A bounded patch and independent-test fixture is recognizably connected to that workload. | We do not reproduce SWE-bench, claim a leaderboard result, or assume test passing proves unrestricted program correctness. The small patch-review task is our adaptation. |
| [AgentDojo primary paper](https://arxiv.org/abs/2406.13352), abstract read | Tool-using agents over untrusted data can be evaluated on both legitimate task completion and specific security properties. | Detecting an unauthorized action is not a general alignment or intent classifier. The paper does not establish effectiveness of our multi-agent immune policy. |
| [Sierra tau2-bench repository](https://github.com/sierra-research/tau2-bench), overview and task interface read | Customer-service evaluation specifies policies, tools and tasks across domains. It motivates an explicit action and state-based contract for the SUPPORT kit. | We did not install or run it. Current APIs, task revisions and user-simulation costs must be pinned before reuse; our initial synthetic task is a simplification. |

The library and previous review remain the project-specific prior-art index. Biological and physical questions use their own source models rather than an unsupported claim that particles, cells and language agents have the same task. Existing descriptions of a runnable model or benchmark must be checked before implementation; no external environment was installed or executed in this contribution.

The review deliberately favors controlled, synthetic examples for the first experiment. Ecological validity then becomes an explicit transfer question: does the same intervention help on held-out realistic tasks after the mechanism survives the controlled comparison? A realistic story without a valid comparison is weaker evidence than a modest, well-identified task.
