# Prospective amendments

## v0.2 — 2026-10-04 UTC, before instrument implementation

Responds to [Dmarz's independent review](../../../dmarz/notes/inbox-reviews-2026-10-04-round2/poietic-review.md). No model responses or reserved evaluation roots have been opened. Owner resolution of this review does not require another routine reviewer.

**P1: arrivals and delays.** Each lineage starts its monotonic deployment clock before initialization. Epoch e's six jobs arrive at exactly `120*(e-1)` seconds, independent of the arm's progress, and expire 120 seconds later. All six jobs in an epoch share its logical source snapshot even when processed late. Queueing, initialization, proposal calls, compilation, migration, reporting and rendering all consume that same elapsed clock. Run arms independently with the same relative schedule and record actual start/provider-time blocks. A barrier never moves release times: after completing or expiring an epoch, boundary proposals can consume the following epoch's time. Expired/unstarted jobs stay failures. A3 may submit one proposal per agent per boundary; proposals that exceed the next job deadline do not rescue it. No native waiting is accelerated as a simulation. A manual 130-second boundary delay must expire the next batch.

**P2: reuse and common primitives.** Repeated-key share is the number of required `(endpoint,entity,snapshot-version)` occurrences whose key appears in at least two jobs in that epoch, divided by all required occurrences, not by distinct keys. Requested 80%/20% overlap is a generator target; the exact achieved numerator/denominator is recorded. Same entity in a new version is a new key. Cross-epoch reuse is allowed only if version and expiry remain valid. Every arm may use the same deterministic fetch, normalization, keyed join, filter, projection, integer arithmetic, sort, limit and aggregation operations. Cache keys include complete inputs, schema, source versions and program hash. Raw and derived memoization can bypass a model in A1; A3 must beat a cache that is allowed to memoize derived results too. A1 does not invent new workflows, while A2's development construction and A3's proposals can build them. Tests distinguish repeated raw bytes, repeated derived work with differing downstream queries, and no reuse. There is no provider-count target.

**P3: advance and stop.** S1 recovery is diagnostic: first two successive post-change epochs with at least 5/6 correct, fresh, on-time jobs each; otherwise not recovered. Proceed to larger *development*, not confirmation, only if all accounting/access/manipulation controls pass, A3 and at least one A1/A2 comparator achieve at least 43/48 successes in every paired root, and at least one accepted change is actually executed. Zero useful changes, no cost advantage, or a simpler comparator winning is a valid feasibility null; report and stop this version without repeated unchanged trials. A cost advantage here is a descriptive lead, not a confidence claim. A competence/control failure prompts a bounded versioned repair and fresh qualification.

S1 physical-call allocations are fixed: 450 per each of 16 arm/root lineages (7,200), 400 A2 construction calls on development roots, and 400 reserved for instrument qualification/repair. Unused quotas do not silently transfer. Their sum is 8,000; dollar/token/time guards can stop sooner. S0 has its separate stage ledger and allowance. A5 performs no useless structural proposal calls after freezing. A4, if later admitted, collects only voluntarily delivered shared packets through a metered interface; direct reads of other private state are forbidden. AgentSlimming-informed prune/replace is an explicitly charged A2 development candidate and MANTA-informed trace repair an A4 candidate, not claimed faithful reproductions.

**S0 interface amendment.** Forty-eight probes per contract are organized as twelve four-step lifecycle cases: fetch/tool selection, data transformation/answer, stale-cache handling, and capability restoration/configuration. The generative contracts emit actual typed actions; Jev selects among supplied finite actions and never generates code. Each step gets one native request, hence 144 logical requests / at most 288 physical calls total. Steps are dependent within cases; the existing 44/48 correct, 48/48 valid and zero protected-access thresholds stay unchanged. Deterministic adapter execution and saved responses establish interface fidelity; Jev's pass does not qualify it for free-form generative proposals. These are bounded engineering probes, not a swarm efficacy result. Repair uses a new disjoint namespace rather than reusing inspected probes.
