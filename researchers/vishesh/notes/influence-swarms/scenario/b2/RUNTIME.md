# B2 operational contract

`worker.py` defaults to admission checks. `--execute` is allowed only with real finite funding, public plan, current exclusive approved-account allocation, original-ledger identity and exact source/runtime receipts. Templates do not provide those authorities.

`parallel_runtime.py` implements bounded independent-cell concurrency; `runtime.py` retains the original accounting and strict decoding/qualification rules with B2's fixed96/1,920 request bounds. `instrument.py` changes only the development assignment subset and corresponding neutral qualification counts; the original evaluation scorer and output schema remain unchanged. `cases.py` clarifies the shared buyer policy while preserving all numeric gold and factual material.

Offline checks include full2,016slot rehearsal, exact old/new label/source comparison, complete threaded evaluation with independent relay and deterministic wire replay, malformed-response stop plus in-flight cost drainage, duplicate-step rejection and a two-request finite-budget race. Scripted success is software validation, not native scientific evidence.

Native artifacts include raw request/response bytes, stable assignment/step metadata, validated outputs, append-only events, original-ledger statuses, source/packet/runtime receipts, explicit missingness and an authored scientific post-mortem. Failed B1 attempts retain their old gate results. A failed B2 diagnostic blocks evaluation, regardless of remaining budget.

Public artifacts contain summaries, scored outcomes, safe events and provenance only. Full request/response records remain in the private retained evidence store and local replay; no raw transcript/archive is automatically uploaded. This narrows publication after platform review without changing model inputs or scientific scoring.
