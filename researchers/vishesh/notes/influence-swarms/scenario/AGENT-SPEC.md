# Actor contracts (documentation; not repository agent instructions)

Six analysts: finance gets quotes; security gets deployment scope; implementation gets migration schedules; service quality gets pilot counts; operations gets pilots and quotes; source audit gets comparison pages. All receive the workload brief and the same leading comparison page. Their objectives are identical; distinct document access is the specialization, not a claim of trained professional expertise.

Each returns a provisional choice or DEFER, confidence, up to three cited findings, and one requested record. Requests are selected by a frozen rotating agenda: first two distinct requests, with deterministic menu fallback. This is not an optimized value-of-information policy. It is held fixed across chair forks. The two check interpreters summarize the exact requested source record and its limitation. No tool returns a secret best answer.

The chair sees the union of source records, reports and check results. The treatment removes only analysts' provisional choices and confidence. It cannot remove negative facts. The chair may choose or defer; the runner records its answer unchanged. Its citations are checked against supplied IDs, not assumed truthful or entailed. Annual cost calculations can be audited against primary records after the run.

The single-reviewer baseline sees the same union from the start and gets two record retrievals. It has fewer calls; the study reports that advantage. All calls are stateless apart from explicit serialized observations; there is no shared conversation or hidden scratchpad. Raw outputs, request hashes, source version, event order and errors are retained. No actor receives case family, world label, target, hidden products, evaluator scorecard or acceptable-set labels.

The scripted reference parser reads only observations. It is a test oracle, not an LLM, and never qualifies a model. Model adapter validation and fixed output schemas must be qualified before paid collection. Seeded fixtures do not promise deterministic API responses.

## Iteration 3 reviewer forks

D2 adds two reviewers and two fresh chairs to each saved team prefix. Reviewers are isolated calls, not conversational continuations. Both see the same complete primary records, reports, checks and arithmetic worksheet; neither sees earlier chair responses. They use the same initial-report output schema, provider/model snapshot and output-token cap. General review asks for the three most useful procurement findings. Targeted approval review asks for one finding per candidate covering every mandatory requirement before comparing costs. Exact prompts and request construction are in analysis/approval_review.py at the run's source commit.

The difference is a **prompt instruction**, not an enforced checklist. The shared schema enforces supplied citation IDs and basic output shape, but does not require candidate coverage or prove factual entailment. Missing coverage is measured as a manipulation limitation; an attractive conditional recommendation is not a successful purchase authorization. The reviewer report is appended to the identical original chair observation, and unchanged chair instructions produce a fresh final action. No code overwrites that action with an approval verdict.

Five decisions share one dossier; the four team-based variants share the same six analysts and two check interpreters. Nominal standalone costs are nine calls for each original team chair, ten for each extra-review variant, and four for the generalist. Collection uses 18 calls per dossier because the common prefix is run only once. Report collection spend separately from these hypothetical standalone workflow totals.
