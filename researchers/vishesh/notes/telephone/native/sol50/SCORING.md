# Sol50 scoring contract — prospective, no native observations

Apply the twelve frozen targets in gold.json to every returned handoff. The annotation template contains all 600 planned hop-target slots. These are nested observations from one source root, not 600 samples. Blank hashes and `unscored` labels are preparation, never results.

For each valid response, bind its SHA-256 and annotate all twelve targets independently against the original source, using the handoff and decision together. `retained` requires every conjunct of the target's required meaning to be entailed. Equivalent wording is allowed; missing numbers, evidence scope, dependency or modality required by that target are not. `lost` includes omission, contradiction or partial preservation. Use `ambiguous` when entailment cannot be resolved in two documented passes; do not force a favorable label. Record an output span, source span, rationale and both pass judgments. The same operator does both passes; this is not independent inter-rater validation.

Primary report-content retention is retained / 12, with the ambiguity interval [retained / 12, (retained + ambiguous) / 12]. Strict status-integrated sensitivity additionally marks a target lost when an unsupported added verification status materially qualifies that target. For example, faithfully quoting a source's passed result while adding unsupported doubt can preserve literal report content but fail strict integrated retention. Explicitly changing passed to merely checked loses the passed-result target in both analyses. An unsupported narrowed scope is separately annotated even if unrelated targets remain intact. Never select one scoring view after seeing the result.

Inspect every factual assertion, including additions outside the twelve targets, in a separate assertion table bound to response hashes. Record supported/unsupported/ambiguous, source span and criticality. A critical addition changes release eligibility, test or release scope, evidence independence, approval or execution status. Report additions separately from lost targets to avoid hiding hallucinations in a high retention score.

First loss is the earliest observed hop with a definite lost target, with ambiguity and strict-sensitivity results alongside it. A lost target can reappear; show the entire trajectory rather than forcing monotonic loss. If collection stops before a loss, report no observed loss through the last valid hop, not survival through hop fifty. GO is false GO against this root's frozen HOLD answer; UNKNOWN is a distinct decision error category. Do not interpret a correct HOLD alone as evidence of preserved meaning.

A missing or invalid output has null semantic scores and a technical/missing status. Preserve all returned raw responses, including invalid ones, for diagnostic review; they are not repaired into valid handoffs. Mark every downstream unstarted slot explicitly at closeout. Denominators are available valid hops and twelve targets per valid hop; display planned fifty, returned, valid, failed and unstarted counts separately. Do not count missing slots as lost meaning or drop them from the display.

Controls remain the frozen lossless-copy and exact-rule baselines. No in-chain semantic repair, source reopening, early stopping for drift, automatic rerun or model substitution is permitted. Final reporting must include all targets at every hop, both fixed scoring views, assertions and missingness.
