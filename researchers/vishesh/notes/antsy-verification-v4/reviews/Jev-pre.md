## Security and deployment

Same exclusively allocated Antsy machine; refresh claims before each stage and extend if necessary. The local machine is only a credential relay, not the experiment worker. It consumes the approved key file internally and forwards HTTPS to the official endpoint. No key transfer to the server, transcript, environment dump, public repo or report. Both tunnel endpoints bind loopback. Generate a finite allowlist of possible frozen actor state/question hashes, including all first-check branches and J0 probes; reject any other payload or duplicate request ID. Ledger updates are durable before dispatch. Log safe statuses, not headers or raw exception bodies. Stop the relay/tunnel after uploads.

Publish this plan and the implementation at an immutable commit; register a condition-specific TLDR and verify its public plan link before the first call, including J0. Every run records source/corpusSHA, requested/served model, provider, actual cost, latency, receipt outcomes and invalid/not-run counts. S0/S1 replays use the same measured mapping. J0 uses a static competence matrix; no artificial swarm animation for isolated probes. Preserve Laya runs and mark Jev as a separate backend in all displays.

## Interpretation and next step

A Jev gain over Laya alone is insufficient: it must also beat the fixed and deterministic baselines, and its call/QA cost must be visible. A failure of basic competence blocks escalation. A valid null result is retained. API authentication and execution remain unverified until the planned qualification actually runs.
