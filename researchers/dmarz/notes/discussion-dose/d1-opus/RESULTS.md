## Configuration caveat

This is not a model-only swap. Opus 5.5 rejects `temperature` and cannot disable thinking, so the request
differs from D1 in four ways: no temperature (D1 used 0), adaptive thinking at `output_config.effort: high`
(D1 disabled thinking), `max_tokens` 16,000 (D1: 2,000) with the visible answer capped at 8,000 characters,
and refusals recorded as their own category. Prompt, schema, evidence and actor inputs are byte-identical to
D1. A difference from Haiku or Sonnet may come from the model, the reasoning allowance or sampling; this run
cannot separate them.

Opus gave no unsupported answers (Haiku 13, Sonnet 3). Its remaining weakness on correlated copies is
over-caution: it abstained on the three answerable fixtures instead of answering. Like both smaller models,
it accepted all six inherited false facts that its only permitted memory supported. **A stronger model did
not solve the merge boundary**: a parent that trusts locally consistent memory still inherits a planted
error.

## What this does and does not establish

Measured: Opus 5.5, under the configuration above, made correct, evidence-consistent choices in 18/18 clean
full-evidence decisions (6 reused, 12 fresh) and never gave an unsupported memory answer in 36 fixtures.

Not established: swarm-level qualification (the report packets were generated by Haiku and no Opus swarm has
run); any discussion or communication effect; population safety; a significance claim. The six reused worlds
were open development examples, and the twelve fresh worlds are clean full-evidence decisions only. The
summary's `model_qualified_for_swarm` flag is false by design: this diagnostic qualifies the model to be
tried in a fresh swarm qualification, not the swarm itself.
