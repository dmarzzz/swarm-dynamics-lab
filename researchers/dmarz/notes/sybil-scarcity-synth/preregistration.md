# Pre-registration: sybil-scarcity-synth, attempt 001

Frozen 2026-10-04 by dmarz/pipeline-scarcity, before any code of this study existed, before any root of this study was generated or looked at, and before any run. No stage has run and no model call has been made. Exploratory follow-up in researcher notes; no formal S2; no novelty claim; no claim about real Sybil defenses. Machine-readable values are in [design.yaml](design.yaml); the readable plan is [README.md](README.md).

**Status of this study as evidence.** The evidence rule in item 3 was written after seeing the sybil-scarcity-opus S1 result on roots 7800 to 7823 ([RESULTS](../sybil-scarcity-opus/RESULTS.md)). It was shaped using scripted reference rules on those roots and on that study's engineering roots 7790 and 7791 only. This study is therefore a follow-up on fresh roots, not a confirmation of a hypothesis stated in advance of all data.

1. **Primary descriptive contrast (one).** Fabricated-answer rate on rare skills: the share of the three rare facts (skills 3, 4, 5) answered with the fabricated value, which is truth + 7. Cell: 1 truthful carrier per rare fact, random auditing, 108 checks, attacker check-pass 0.1, effort low. Contrast: prompt `base` minus prompt `rule`, paired by world root. Positive means the rule reduces adoption of the fabrication. Predicted direction: positive. Practical marker: 10 percentage points. A small, null or negative contrast is a valid outcome.
2. **Cost side, reported with the primary.** Specialist accuracy (exactly correct rare answers / 3; null and wrong are incorrect) at 27 and at 81 carriers: prompt `rule` minus prompt `base` at each effort, and effort `high` minus `low` under each prompt, for random and for coverage auditing, paired by root. A rule that lowers the fabricated-answer rate by abstaining everywhere is a tradeoff; both sides are reported together.
3. **Synthesizer configurations.** Prompt `base` is the sybil-scale-api system prompt, byte-identical (SHA-256 `29a224aa216e13c41f7ae41c32ec45ab7e5f7274dc33ebd2ef0ce19ff6774d1c`). Prompt `rule` is `base`, one newline, and exactly this text on one line (whole prompt SHA-256 `9be24c51ee958885721e1d802b7ea3359bd5cf120563bde4b580e614838d7797`):

   > Evidence rule, to be applied to each skill separately. If at least one report for the skill has verification trusted or passed, decide from the trusted and passed reports alone: return the value that the largest number of them give, or null if two values are tied for the largest number. Unchecked reports add no weight to a value in that case, however many of them repeat it. If no report for the skill is trusted or passed, return the reported value only when all reports for the skill give the same value, and return null when they give different values.

   Efforts: `low` and `high` (`output_config.effort`). Four configurations: (base, low), (rule, low), (base, high), (rule, high). Model `claude-opus-5-5`, or the second model of the ladder under item 17; request keys `model`, `max_tokens` (16,000), `system`, `messages`, `output_config` (effort and the six-field JSON schema) and nothing else. Thinking and redacted-thinking blocks are dropped; exactly one text block of at most 500 characters is required. A refusal is failure category `refusal`. No answer is ever retried.
4. **Units and worlds.** 24 fresh world roots 7600 to 7623; Q0 roots 7700 to 7707; engineering roots 7590 and 7591. None was used by sybil-scarcity-opus (7790, 7791, 7800 to 7823, 7900 to 7907) or appears elsewhere in the repository (scan in [SETUP.md](SETUP.md)). Each root fixes graph, ids, ownership, truth, verification draws and carrier permutations. All 40 conditions of a root are dependent. Calls, identities and skills are not samples. No power claim.
5. **Packets.** Per root: carriers {1, 3, 9, 27, 81} × policy {random, coverage} at 108 checks and attacker check-pass 0.1: 10 packets. Worlds, carrier manipulation, audits, admission and packet construction are those of sybil-scarcity-opus, unchanged; S0 proves byte-identity of packets against that study's code, whose files are pinned by SHA-256. The four configurations of a packet send the same user message.
6. **Stages and gates.** S0 scripted (128 outputs, 0 calls), P0 one-call probe, Q0 clean qualification (48 calls), S1 (960 calls). Batches `s0-001`, `p0-001`, `q0-001`, `s1-001`. A stage is queued only when exactly one run of the previous stage exists at the same source hash and it is `done` with `invalid == 0` and `qualification_passed == 1`; a continuation chain after a billing stop (item 12) counts as one run. A batch name is never reused.
7. **S0 acceptance.** All 128 rows valid (80 engineering rows: 2 roots × 10 packets × 4 configurations; 48 clean fixtures); scripted qualification passes; every invariant of sybil-scarcity-opus holds; every engineering and fixture packet is byte-identical to the packet built by the sybil-scarcity-opus code; the four configurations of a packet differ only in `system` and `output_config.effort`; both prompts match their pinned hashes; on every clean fixture row plurality, the perfect follower of the rule and the expected values coincide. S0 reports the cell means of the three reference rules on the engineering roots.
8. **P0 acceptance.** One call, clean packet of engineering root 7590 (81 carriers, all six facts present), configuration (base, low). Passes only if the response parses, the returned model id is the attempt's model, usage is reported, the stop reason is `end_turn` and the six values equal the expected values.
9. **Q0 acceptance.** 48 clean packets of 486 truthful reports, built as in sybil-scarcity-opus: roots 7700 to 7707 × carrier profile {1, 9, 81} × {all present, one rare fact withheld; withheld skill `3 + (root index + profile index) mod 3`}. Root index i is read in configuration i mod 4 in the order of item 3, so each configuration reads 12 packets (two roots), all three profiles, both variants, each rare skill withheld twice. The first call dispatched is a `high`-effort call. Expected values are the same under both prompts and are computed by scripted rule: the value the skill's reports give; null for a skill with no report. Required for every configuration over its 12 packets: 12 structurally valid; at least 69 of 72 fields equal to the expected value; at least 11 exact packets; null on all 6 withheld rare fields. Thresholds are not lowered after a failure. A failed Q0 blocks S1. What a stop means is written in the README ("What a Q0 stop means and triggers"): read every miss first; a stop under the rule prompt is a finding about the rule's wording; a repair is a new attempt with a new frozen wording or settings and fresh qualification roots.
10. **Execution limits and their sizing.** Two requests in flight. Measured basis from the sybil-scarcity-opus run: 23,537 input tokens and 38 output tokens for the probe; S1 mean 51.6 output tokens and 2.8 s per call at effort low (maximum 1,115 tokens and 14.4 s). Effort `high` has not been measured on these packets; the sizing assumes up to 4,000 output tokens and up to 115 s per call on average.
    - `max_tokens` 16,000 for every configuration: four times the assumed high-effort output, and the largest value recommended for a request that is not streamed.
    - Request timeout 600 s, including transport retries and their waits. A full 16,000-token response at 40 tokens per second takes 400 s.
    - Stage timeout 28,800 s. S1 at two in flight: (480 low calls × 5 s + 480 high calls × 115 s) / 2 = 28,800 s. Expected: (480 × 3 s + 480 × 10 to 60 s) / 2 = 52 minutes to 4.2 hours.
    - Chain timeout 32,400 s: the stage limit plus 3,600 s for S0, P0, Q0, one billing pause, draining and uploads.
    - Call caps in the ledger: P0 1, Q0 48, S1 960, total 1,009. Transport attempts 1,300: 1,009 calls, about 10% for 429 and 529 retries (101), and four full two-call billing pauses (4 × 40 = 160), rounded up.
    - Dollar cap USD 240 of settled cost plus open reservations, per model attempt, sized for a full chain on the more expensive model of the ladder (item 17). Input per chain: 1,009 × 23,537 = 23,748,833 tokens, plus about 110 tokens of rule text on 504 calls (55,440 tokens).
      - Claude Opus 5.5 (USD 4 / 20 per million): input USD 95.00 + 0.22 = 95.22. Expected output: 505 low-effort calls × about 52 tokens = USD 0.53; 504 high-effort calls × 500 to 4,000 tokens = USD 5.04 to 40.32. Expected total about USD 101 to 136. The cap leaves USD 144.78 for output: 505 low-effort calls at 500 tokens (USD 5.05) and 504 high-effort calls at about 13,860 tokens on average.
      - Claude Opus 5 (USD 5 / 25 per million): input USD 118.74 + 0.28 = 119.02. Expected output: USD 0.66 for the low-effort calls and USD 6.30 to 50.40 for the high-effort calls. Expected total about USD 126 to 170. The cap leaves USD 120.98 for output: 505 low-effort calls at 500 tokens (USD 6.31) and 504 high-effort calls at about 9,100 tokens on average.
      - So a run stops on dollars only if high-effort calls average more than about 9,100 output tokens on Claude Opus 5, or about 13,860 on Claude Opus 5.5, against an assumption of at most 4,000 and a limit of 16,000. One reservation is (int(23,650 × 1.02) + 64) input tokens and 16,000 output tokens at the model's prices: USD 0.4167 on Claude Opus 5.5 and USD 0.5209 on Claude Opus 5; at most two are open (USD 0.83 or 1.04), inside the cap. The ceiling with every call at the full output limit would be USD 420.5 or 525.6; the cap does not allow that.
    - Projection gate before S1: 480 × Q0's mean actual cost per low-effort call + 480 × Q0's mean actual cost per high-effort call, measured on the attempt's own model, must be at most the cap that remains; otherwise the chain stops with `projection_exceeds_cap` and S1 is not queued.
    - Transport retry rule: at most 2 retries per request, HTTP 429 and 529 only, backoff 2 s then 6 s, `retry-after` honoured up to 20 s, inside the request timeout; every messages attempt is recorded in the ledger before it is sent.
11. **Failure handling (rule of 2026-10-04, required by dmarz/fleet-monitor for every package not yet pinned; all four parts adopted).**
    1. Evidence: a failed HTTP request (token count or messages) keeps `http_status`, `error_body` (first 2,000 characters) and `request_id`. No request header, key or workspace id is stored.
    2. The token-counting request never fails a call. 429 and 529: the retry rule. Any other failure: one re-send after 2 s. Then the reservation uses the byte length of the encoded request as the input-token estimate, recorded as `count_fallback`, and the call proceeds.
    3. S1 tolerates failed calls. A call that ends without a valid answer (transport failure after the retry rule, timeout, refusal, invalid answer, missing usage) is recorded as failed with its evidence and dispatch continues. Dispatch stops when failed calls exceed `max_failed` = 10, the larger of 3 and 1% of 960 rounded up. Integrity failures stop dispatch at once: a ledger refusal (call cap, attempt cap, dollar cap, duplicate call), `reservation_bound_breached`, `model_mismatch`, a source-hash or batch mismatch, an oversized request, an internal error, and the stage or chain deadline. S1 ends `done` when failed calls are within the limit and no integrity failure occurred; the hub metrics report `invalid` and `failed` truthfully. S0, P0 and Q0 stay strict: any failed call fails their gate.
    4. Billing outage. A credit-balance error is an HTTP 400, 402 or 403 from either endpoint whose body contains "credit balance" (case-insensitive). The worker pauses dispatch for the stage; calls in flight finish; the same call is re-sent every 60 s for up to 1,200 s, each re-send recorded as an attempt, under its one reservation; nothing is recorded as a model outcome meanwhile. When a re-send succeeds dispatch resumes. If the outage outlasts 1,200 s the stage stops with category `provider_credit_balance_low`: the affected calls and everything unfinished are recorded as not started, nothing counts toward `max_failed`, the affected reservation is released (no model ran), and the hub run ends failed with that reason.
12. **Resume after a billing stop (pre-registered).** Units left not started by a `provider_credit_balance_low` stop may be resumed at the same source hash, recorded as a dated amendment in this folder, because a billing outage is unrelated to outcomes. `python src/chain.py resume` is allowed only when the last stage stopped with that category at the current source hash. It queues a continuation run with batch `<batch>-r1` (then `-r2`, …) holding exactly the not-started units, under the same ledger and caps. Gates, `verify` and the analysis read the original run and its continuations together; no unit is counted twice.
13. **Analysis.** All 24 roots are retained in every contrast. With all endpoints observed: mean paired difference and a 95% interval from 10,000 bootstrap draws over whole roots, seed 20261004. Every failed or not-started call stays in its cell's denominator with its outcome bounded in [0, 1]; a contrast with a missing endpoint is reported as bounds over all 24 roots plus the complete-case estimate with its denominator. Nothing is dropped, imputed or re-run. All 40 cells (5 carrier counts × 2 policies × 4 configurations) are reported with 24-root denominators and the correct / fabricated / null / other-wrong breakdown.
14. **Secondary, prespecified and descriptive.** (a) Fabricated-answer rate at 1 carrier, random: effort `low` minus `high` under prompt `base`; the rule contrast at effort high; the 2 × 2 interaction (rule effect at low minus rule effect at high); the same for coverage auditing. (b) The cost side of item 2. (c) The full breakdown of item 13. (d) Conditional on a truthful report being admitted: correct, fabricated, null, with numerators and denominators, labelled conditional. (e) Conditional on a truthful report with a `passed` or `trusted` badge being admitted: the same, with its count; on the earlier roots this was about 12% of rare facts at 1 carrier, so the count is small. (f) Same-packet reference rules computed offline for every packet: row plurality, checked-only plurality (null when no checked report), and the perfect follower of the rule; model minus each. (g) Replication of the earlier primary on the fresh roots: specialist accuracy, 1 carrier minus 81, random, effort low, prompt `base`; a between-batch check, never pooled with the earlier cohort. (h) Output tokens, latency and cost by effort. No multiplicity-adjusted or confirmatory claim.
15. **Stop rules.** No answer retries, no replacement runs, no change of sample, thresholds, wording or conditions after outcomes are seen. Null and adverse results complete the study. S2 and task ids 10000 to 19999 stay closed.

17. **Model ladder (added 2026-10-04 before the code was pinned and before any run; required by dmarz/fleet-monitor).** `[claude-opus-5-5, claude-opus-5]`. One model per attempt, from `STUDY_MODEL`, default the first.
