## Setup

Changes from q0-006, all forced by the model's accepted parameters (run-queue 196: "Thinking and effort settings as in d0-003 unless the model requires otherwise"):

- `inference: {thinking: {type: adaptive}, effort: high}`, temperature omitted. The API rejected `disabled` and named `adaptive` with `output_config.effort` as the control. Effort stays at d0-003's high.
- Output cap 4,096 tokens (was 350). With adaptive thinking the cap covers thinking and the answer together. On a trivial input the probe used 0 thinking tokens; on study turns the amount is unknown, and a truncated response would be recorded as a nonterminal failure, so the cap is set well above d0-003's 42 output tokens per call.
- Adapter: a response may contain `thinking` or `redacted_thinking` blocks followed by exactly one `text` block. The text is parsed exactly as before; thinking content is never stored, only the block types and the reported thinking-token count. Any other content shape remains `unexpected_content`.
- Adapter: for an HTTP error, retain the provider's error `type` and the first 300 characters of its message (no headers, no credentials), so a rejected request explains itself.

Everything else is identical to q0-006: model `claude-opus-5-5`, roots 244/253/256 and their 24 assignments, prompt, schema, menus, task generator, evaluator, roles, schedule, contract v2, 40 turns, 16,000 request bytes, 90-second timeout, 7,200-second stage limit, one worker, no retries, thresholds. The roots were transmitted in q0-006's rejected requests but no inference ran on them.
