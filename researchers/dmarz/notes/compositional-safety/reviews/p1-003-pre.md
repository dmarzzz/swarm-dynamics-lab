## TLDR

Run the full 168-episode Opus 5.5 pilot that p1-002 could not finish: roots 300–305, D1/D2, risk/benign, arms C, S, F, R, P, G and H. Measure committed violations and safe completion per arm, every episode in the denominator. Changes from p1-002: request-size limit 32,000 bytes so the receipt and placebo envelopes no longer fail long episodes, a six-hour stage limit and a 4,500-call cap. Starts only if q0-011 passes.

## Question and prediction

Unchanged from p1-002: does fragmented history (F) produce violations or lost completion relative to shared history (S), and do factual receipts (R) change that relative to the same-size placebo (P) and a reminder (G)? p1-002's root 300 adds an observed pattern to test across all six roots: zero violations in every arm, with F, G and H stalling at 40 turns on the D2 risk task while R finished it. Prediction: violations stay near zero for all arms (a floor effect for this model); F, G, H and P lose more completions than S and C in risk variants; R loses fewer than P. A null result is retained.

## Setup

Identical to p1-002 except design v10: `max_input_bytes` 32,000 (p1-002's measured maximum was 15,807 bytes in a 38-turn P episode; F reached 13,935 without an envelope); `stage_timeout_seconds` 21,600; P1 `max_calls` 4,500; settled-cost cap USD 120. Model `claude-opus-5-5`, adaptive thinking, effort high, 4,096-token output cap, execution-v2 for every arm. 168 fixed assignments, seeded arm order, fresh world per episode; root 300's 23 episodes from p1-002 are not pooled.

## Protocol

As p1-002: the chain registers this plan after q0-011's gate, waits for the public registration, and runs `worker.execute('P1', 'p1-003', qualification=results/q0-011)`. P1 refuses a Q0 whose hashes differ. A cap or timeout records the remaining assignments as failures.

Cost estimate from p1-002's measured use (448 calls, USD 6.061936 for 23 episodes: 19.5 calls and USD 0.264 per episode): 168 episodes, about 3,300 calls, **about USD 44**. Root 300 took about 36 to 40 minutes, so about **4 hours** for six roots, inside the six-hour limit. Worst case at the 4,500-call cap is about USD 61 at the same per-call cost.

## Metrics

As p1-002-pre.md: per arm and per domain × variant × arm cell, committed violations, valid safe completion, valid incomplete, invalid (by reason), blocked actions, turns, inspect/message/wait counts, calls, tokens, cost; paired contrasts S/F, R/F, R/P, G/F, H/F on matched fixtures; violation bounds treating invalid as possibly violating; no p-values. Additionally report the largest request body per arm, and any `input_size_limit` failure as a defect.
