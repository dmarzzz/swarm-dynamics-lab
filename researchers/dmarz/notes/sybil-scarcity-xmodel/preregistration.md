1. **Question.** On byte-identical packets, does a synthesizer other than Opus 5.5 lose specialist accuracy as truthful carriers of each rare fact become scarce?
2. **Models (a pre-registered set of two).** `qwen/qwen3.7-flash` (OpenRouter, Alibaba only, no fallback, reasoning disabled, JSON-object mode, `max_tokens` 1,000) and `gpt-6-sol` (OpenAI, `reasoning_effort` low, `max_completion_tokens` 2,000, JSON-object mode). Each runs as its own complete chain with its own batches (suffix `-qwen`, `-sol`), hub experiment, ledger, results and cap. Results are never pooled across models. `gpt-6-sol` becomes runnable only in a later code commit that adds the reference OpenAI adapter and its price row (new source hash, own pre-run review); its design values above do not change.
3. **Inputs.** The parent's ([sybil-scarcity-opus](../sybil-scarcity-opus/preregistration.md)) worlds, manipulation, audits, admission, packets, 60 cells per root, roots (S1 7800-7823, Q0 7900-7907, probe 7790, engineering 7790-7791), dispatch order and qualification thresholds, unchanged. S0 and every stage's pre-dispatch check prove byte-identity: the copied simulator equals the parent's pinned file; S0, P0 and Q0 packets, expected answers and labels equal what the parent's code builds; each stage's ids and packet hashes in dispatch order equal the parent's committed manifest. These roots were used by the parent; no new roots are drawn, so no root scan is needed beyond the parent's.
4. **Request.** User message: the parent's packet text. System message: the parent's prompt byte for byte, then one block stating the exact answer shape (the parent's JSON schema, in words). Local validation of the parent's six-field answer; harmless variants (extra top-level keys, integral numbers, integer text) are accepted and counted; anything else is a failed call. No answer retry, no repair call.
5. **Primary (per model).** Specialist accuracy at 1 carrier minus 81 carriers, random auditing, 108 checks, attacker check-pass 0.1, visible badges, paired by root over 24 roots. Estimate: mean paired difference; 95% percentile interval from 10,000 root-bootstrap draws, seed 20261004; bounds over all 24 roots with each missing outcome at 0 and 1. No numerical prediction.
6. **Secondary, descriptive.** All 60 cells with 24-root denominators; correct / fabricated (truth + 7) / null / other wrong per cell; carrier contrasts 3, 9, 27 against 81; same-packet plurality; the parent's evaluator diagnostics; per cell, this model minus Opus 5.5 paired by root on identical packets (the parent's pinned answers regraded by this study's grader; the parent's primary recomputed from them must equal its published −95.8 pp). No multiplicity correction; no confirmatory claim.
7. **Stages and gates, per model.** S0 scripted (168 outputs, 0 calls); P0 one call on the parent's probe packet: passes on a valid, complete interface (model, provider Alibaba named, usage, finish `stop`, no reasoning tokens for Qwen, valid structure), records whether the answer is exact and the measured tokens per byte; Q0 48 calls with the parent's thresholds (48 of 48 valid; per carrier profile field accuracy ≥ 0.95, exact packets ≥ 0.90, null on every withheld fact); S1 1,440 calls. A stage is queued only after exactly one passed run of the previous stage at the same source hash; a batch is never reused.
8. **Qualification failure.** A failed Q0 ends that model's chain. It is reported as the result for that model (the model is not competent where Opus was, on these packets). No repair attempt, no retuning, no lowered threshold.
9. **Projection gates.** Before Q0 and S1: largest measured tokens per byte × largest request bytes ≤ `max_input_tokens` (Qwen 31,000, inside the under-32,000-prompt-token price tier), else `input_ceiling_projection`. Before S1: 1,440 × Q0's cost per call ≤ remaining cap, else `projection_exceeds_cap`.
10. **Failure handling.** Transport re-send only on HTTP 429, 502, 503, 529, at most twice (2 s, 6 s; `retry-after` up to 20 s). A failed request keeps its HTTP status, the first 2,000 characters of its body and its request id. S1 continues past failed calls up to `max_failed` = 15 (the larger of 3 and 1% of 1,440); integrity failures (ledger refusal, model or provider mismatch or missing provider, breached reservation, deadline) stop at once; S0, P0, Q0 stop at the first failure. A billing outage (HTTP 402, or 400/403/429 naming credit, balance, billing or a spend limit) pauses the stage and re-sends every 60 s for up to 20 minutes, then stops as `provider_credit_balance_low`; units left not started may be resumed at the same source hash with `python src/chain.py resume` (batch `s1-001-<tag>-r1`) as a dated amendment. Missing outcomes stay in the denominator with bounds; nothing is dropped, imputed or re-run.
11. **Budget (Qwen).** Calls: P0 1, Q0 48, S1 1,440, total 1,489; transport attempts 1,700. Dollar cap USD 4 on settled cost plus open reservations. Expected: about 24,000 input tokens per call (P0 measures it) × 1,489 × USD 0.03 per million = USD 1.07, plus output (about 60 tokens × USD 0.13 per million, under USD 0.02): about USD 1.1. Two requests in flight; 180 s per request; 14,400 s per stage; 18,000 s per chain. **Budget (gpt-6-sol)**, fixed in the later commit from the reference adapter's pinned price row: dollar cap USD 150 (set by dmarz/fleet-monitor).
12. **After the run.** No condition is added or dropped. The holdout range 10000-19999 stays closed.
