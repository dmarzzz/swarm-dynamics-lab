## Design and assessment

- Closest evidence and comparator: the parent, on the same packets. The parent's 1,440 answers are pinned (`records/s1-episodes.jsonl.gz`, SHA-256 in design.yaml) and regraded by this study's grader; the parent's primary recomputed from them is −95.83 pp, equal to its published value (rehearsal check `a_parent_primary_reproduced`). Same-packet plurality is reported per cell.
- Units: the parent's 24 world roots (7800-7823), each paired across 60 cells and paired with the parent's row of the same id and packet hash. Calls, identities and skills within a root are dependent.
- Coverage and boundaries: no new roots. The inputs are the parent's, so the roots have been used before, by design; the parent's outcomes on them are public and are the comparison. The rehearsal ran the plurality stub over the S1 packets to exercise the pipeline; its outputs were deleted; its headline (primary −97.2 pp for plurality) is a scripted value, not model evidence. Holdout 10000-19999 untouched.
- Manipulation and byte-identity: `study.parent_equivalence` runs before any call of every stage and blocks the stage on a difference: the copied `sim.py` equals the parent's pinned file; for S0, P0 and Q0 every packet text, expected answer, evaluator label and truth vector equals what the parent's own `study.py` builds (loaded from the parent directory after its SHA-256 is checked); for every stage the list of `<id> <packet sha256>` lines in dispatch order equals the parent's committed `manifest.json` (S1: 1,440 lines, 1,207 distinct packets). The parent's own invariants (nested carriers, identical audits and admission across carrier counts) therefore carry over unchanged.
- Evaluator, truth separation, controls: packets hold only `node`, `skill`, `claim`, `age`, `activity`, `verification`, and no forbidden word (checked per stage); the system message is checked for evaluator words. The fabricated value (truth + 7) is graded wrong and counted as `fabricated`; null is counted separately; correct + fabricated + other wrong + null = 1 per row (tested). Positive control for the gate: the rehearsal's never-abstaining stub fails Q0 and the chain stops with no S1 run.
- Answer validation (lesson from the flagship's stopped probe): before pinning, each structural check was asked whether a harmless variant of a correct answer would fail it. Accepted and recorded per row (`normalized`), and tested end to end through the real adapter: reordered keys, pretty-printed or whitespace-padded JSON, values as integer text ("29") or integral numbers (29.0), extra top-level keys besides `values`. Still failing, by decision: booleans, fractions, other text, a missing or extra skill key, nested values. One remaining strict point sits in the unchanged reference adapter: text around the JSON object (a code fence) is `invalid_json`. JSON-object mode should not produce it; if it does, S1 tolerates 15 failed calls and Q0/P0 stop, and the kept `answer_text` shows it.
- Primary metric: specialist accuracy at 1 carrier minus 81, random auditing, 108 checks, attacker pass 0.1, per root; mean over 24 roots, 10,000-draw root bootstrap (seed 20261004), bounds with missing outcomes at 0 and 1. Limits: one synthetic task; model and request format differ together from the parent.
- Timing semantics: none inside a call; the replay shows completion order.
