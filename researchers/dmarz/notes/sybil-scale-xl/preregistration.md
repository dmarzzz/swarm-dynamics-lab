# Pre-registration: sybil-scale-xl v1

2026-10-04, dmarz/scale-xl. Committed before any fleet stage or model call of this study.

1. Protocol: the [frozen sybil-scale-api protocol v1](../sybil-scale-api/preregistration.md), items 1–9, with these changes and no others. Population sizes are N = 972, 2,916 and 8,748 simulated identities (the parent used 36, 108, 324 and 972). The graph construction, arms, attacker share (25%), check reliabilities (honest pass 0.90; attacker pass 0.10 or 0.90), fixed (4) and proportional (N/9) check budgets, admission seats (N/2), badge modes, system prompt, JSON schema, temperature 0, 500 output tokens and the evaluator are unchanged. The model is the parent's `claude-haiku-4-5-20251001`.
2. Qualification packets are resized to the S1 packet size. The parent's `full` packet contained all N reports, which at N=8,748 would exceed Haiku's 200k-token context. Q0 here uses `sample` (a seeded uniform sample of N/2 clean reports, all six skills present) and `common_only` (the N/2 common-skill identities, so specialist facts are missing and must be abstained on). Thresholds per size are unchanged: 100% structural validity, ≥95% field accuracy, ≥90% exact packets, 100% missing-evidence abstention. A failure at any size stops the study before S1 and is reported as a result about Haiku at that packet length.
3. Primary descriptive contrast: coverage, visible badges, attacker pass 0.10, rare accuracy, proportional (N/9) minus fixed (4) checks at N=8,748, paired over the 24 world clusters 6000–6023, 10,000-draw world-cluster bootstrap with the parent's fixed seed. Useful difference 10 points. Attacker seat share is always reported with it.
4. Secondary, predeclared and descriptive:
   a. Scaling trend: for coverage/visible/pass 0.10 proportional checks, rare accuracy and attacker seat share at 972, 2,916 and 8,748. The question is whether proportional checking keeps specialist accuracy near the parent's 98.6% as N grows ninefold, or degrades.
   b. Synthesis at length: model minus same-packet plurality accuracy per cell. The parent found Haiku 98.6% versus plurality 100% at 972 (strong/proportional coverage). A widening negative gap at 2,916 and 8,748 would indicate a long-packet integration failure of the model rather than of the admission mechanism.
   c. Test-retest anchor: every N=972 S1 assignment has the same id and packet as the parent's S1 (run sybil-scale-api/56defc84). Per cell, this study minus the parent's rare accuracy, paired by world, measures model and API drift between the two runs. No parent call is repeated outside this anchor.
   d. Coverage versus random at equal budget, weak-check (pass 0.90) security cost, and visible minus hidden badges, as in the parent.
5. Stop rules: no retries; the first failed call stops new dispatch and the remaining assignments are recorded as not started. A new attempt needs a new pre-run assessment and attempt id. Cohorts (this study, the parent and the Sonnet replication) are never pooled. No condition is dropped or added after seeing results. Null and adverse findings complete the study. S2 and the holdout range 10000–19999 stay closed.
6. Budget: the study ledger caps conservative byte-based reservations at USD 500 and 2,100 attempted calls. Reservations are an upper bound (one token per request byte); expected actual spend is in the README. dmarz authorized spending beyond the earlier shared USD 500 allowance for this run ("don't worry about the budget", 2026-10-04).
