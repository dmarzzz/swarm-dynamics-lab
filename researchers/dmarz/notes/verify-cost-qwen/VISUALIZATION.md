# Visualization mapping v1: verify-cost-qwen

- Mapping version: v1, bound to the source hash in [READY.yaml](READY.yaml). Renderer: `src/render.py` (Pillow only). No parent mapping; the layout is specific to this study.
- Run bindings: each stage is one hub run of experiment `verify-cost-qwen` with params `stage`, `batch` (`s0-001`, `p0-001`, `q0-001`, `s1-001`, and `s1-001-r<n>` for a continuation after a billing stop), `source_hash` and `code`. Each row binds layout seed, error probability e, UNKNOWN cost U and representation.
- Behaviour to show: whether the choice between checking and exploring follows the case (regret near 0 everywhere) or a constant habit (regret in the six cases where that habit is wrong), and whether the table and the prose differ, layout by layout.
- Status: the renderer is implemented and tested offline on scripted rows. No frame of a paid stage exists, because nothing has run.

| Recorded signal / exact field | Unit, denominator or derivation | Visual encoding | Actor-visible or evaluator-only | Missing / failure display |
|---|---|---|---|---|
| `evaluation.expected_regret` per cell | mean over valid rows of a (e, U, representation) cell; 24 layouts per cell in S1 | two 4 × 3 grids, top left: rows e 0.05 to 0.80, columns U 0.10 to 0.75, one grid per representation; number in the cell; cell colour from green (0) to red (the case's largest regret, \|e − U\|) | evaluator-only | a cell with no valid row is hatched and says "no valid answer"; a cell with some missing rows says "n missing" in red |
| `evaluation.optimal`, `evaluation.optimal_action` | optimal choices / valid rows of the cell, and the case's optimal action | text line in each cell, for example "21/24 explore" | evaluator-only | counts cover valid rows only; the denominator shows it |
| primary: per-layout table-minus-prose regret | mean over the twelve cases of regret(table) − regret(prose), one value per complete layout | top right: one dot per layout in seed order, y from −0.32 to +0.32 (the design's bound); teal below zero, amber above; white line at the mean; text with the mean, the number of complete layouts and the 95% t interval | evaluator-only | a layout with missing units is a red vertical bar spanning its bounds, never a dot; the bounds over all assigned layouts are printed |
| regret per case against the comparators | per case: prose bar, table bar; always-check and always-explore regret as horizontal marks where that policy is wrong | bottom left: 12 bar pairs, y from 0 to 0.75; amber prose, teal table, white mark always-check, red mark always-explore; "R" above a reliable-source case flagged as a regression | evaluator-only | "?" in place of a bar with no valid row |
| reliable-source regression | in strata with e ≤ 0.20: optimal count table minus prose; flagged at −3 or lower | text line, bottom right, red when any stratum is flagged | evaluator-only | counted over valid rows |
| stage accounting | valid / assigned, failed, not started, pending; calls, transport attempts, input and output tokens; stage dollars from usage; ledger committed dollars and the cap; elapsed seconds | text lines, bottom right (the cost panel) | — | zero until the first call |
| failures by category | units without a valid answer, by failure category or stop reason | red text line, bottom right | — | absent when there is none |
| qualification fixtures | one square per fixture and representation | bottom right: green optimal, red not optimal, grey no valid answer | evaluator-only | grey |

- Time axis: completion order of calls. It is not agent-interaction time: every call is an independent one-step decision with no memory. The replay shows the panel after each eighth of the recorded rows.
- Event markers: none inside a stage. Stage boundaries are separate runs with their own frames. A billing pause is reported in the hub progress message and in the summary (`billing_pauses`, `billing_pause_seconds`, `billing_affected_calls`), not in the frame.
- Cadence and bounds: one `initial_frame.png` before the first call; `progress.png` at most every 20 s and once when dispatch stops; `final_frame.png`; `replay.gif` with at most 8 frames at 900 × 600, 700 ms per frame (about 250 kB for S0 locally). PNG frames are 1800 × 1200 RGB.
- History for replay: `episodes.jsonl.gz` in completion order (one terminal row per unit with answer, evaluation and accounting), `assignments.jsonl.gz`, `requests.jsonl.gz` (the exact system and user text of every request), `analysis.json`, `failures.json`. Any frame can be rebuilt from these without a model call. For a continuation the frames cover the earlier runs' rows and its own together.
- Destination: PNG and GIF artifacts of the hub run. No custom player is assumed. The final PNG is the static fallback.
- Public-safe fields: frames show aggregates only. No credential, address or request text appears. Actor inputs never contain truth, seeds, the optimal action or any evaluator field; a selftest and an S0 invariant check that.
- Honesty rules: no value is drawn for a cell or layout without a valid answer; missing units appear as missing and as bounds. S0 frames show the scripted analytic policy (regret 0 everywhere), which is not model evidence. No model call is made for rendering.
- Synthetic-trace validation (selftest `test_frames_for_empty_partial_failed_and_final_states`): an empty frame, a partial frame, a frame with a failed row, the scripted S0 rows and qualification-only rows; a replay GIF whose frame count and size are checked.
- Acceptance checks after a run: initial frame shows 0 valid; final frame counts equal `summary.json`; cell numbers equal `analysis.json` `cells`; the primary line equals `analysis.json` `primary`; `chain.py verify` confirms artifact checksums.
- Rendering failure policy: a failed progress or final frame is recorded in `summary.json` `reporting_errors` and does not stop calls or fail the stage on its own; a missing artifact then fails `chain.py verify` (`hub_has_every_artifact`), and the frames can be rebuilt offline from the saved rows.
- Post-run artifact owner: the operator of the chain and dmarz/pipeline.
