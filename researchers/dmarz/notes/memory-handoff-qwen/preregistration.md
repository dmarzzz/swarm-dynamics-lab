# Pre-registration: memory-handoff-qwen, attempt 001

Frozen 2026-10-04 by dmarz/pipeline-memory, before any code of this study existed and before any run. No stage has run and no model call has been made. Exploratory; no formal S2; no novelty claim. The first version is commit `bee94550`; the changes made while the package was built, all before any run, are listed at the end.

Source of the design: [research program v5](../overnight-program-2026-10-04/program.json), sections "M · Can successors repair inherited false memory?", "M · Four handoffs and six memory states", "M · Primary comparison and useful-memory guard", "Qualification for the three focused follow-ups" and "One model and a finite portfolio", and session brief 4. The program's design is frozen and implemented as written; the dated implementation notes in the [README](README.md) say where a detail had to be fixed because the program leaves it open. Machine-readable values are in [design.yaml](design.yaml).

1. **Primary descriptive contrast.** Inherited error under content-bound retrieval minus inherited error under metadata-only resolution, averaged equally over the misquote and stale states within each root: `d_r = ((IE[r, misquote, content] − IE[r, misquote, metadata]) + (IE[r, stale, content] − IE[r, stale, metadata])) / 2`, 24 root-level values. Inherited error is 1 when the successor's value equals F + delta (the false value carried by the inherited memory, plus the task's delta) and 0 otherwise, including null. Expected direction: decrease. A successor that follows the stated source policy exactly gives −0.5 in every root. A contrast near 0, or a positive one, is a valid outcome.
2. **Utility guard.** Clean-memory correct completion: in the clean state the value equals T + delta. Reported for raw, metadata and content with a 95% Wilson interval over the 24 roots, and as paired differences content minus raw and content minus metadata with bootstrap intervals. It is a guard reported with its uncertainty, not a non-inferiority guarantee.
3. **Units.** 24 roots 5401 to 5424, 8 per task family. A root fixes the family, the requested fact, T, F, delta, the three other facts and every record ID. The 24 assignments of a root are dependent. Calls are not independent samples. No power claim.
4. **States (6).** clean; misquote (the note misquotes a genuine source); stale (the note cites a superseded version; the current version says T); copies (three records of one origin cited as three reports, with a two-origin requirement); contradiction (two equal-authority origins disagree); false_original (the cited authoritative source itself says F). Within a root the three other notes are identical in every state. The evaluator's truth is never placed in a message: a packet contains T only where a genuine record or note of that state carries it (clean; contradiction; content-bound retrieval in misquote and stale).
5. **Policies (4).** raw (notes only); metadata (notes plus origin, authority, version and current version of every cited record); content (as metadata plus every cited record in full and the current version of a superseded origin); reset (no notes, no registry, no records, no replacement facts). The system message is one constant for all calls. The user message always has the same four parts. Nothing names the state or the policy.
6. **Reference.** The actor-evidence reference is the stated source policy applied to the visible message by the copied benchmark resolver. Table (T, F, null): clean T T T null; misquote F F T null; stale F null T null; copies F null null null; contradiction null null null null; false_original F F F null (columns raw, metadata, content, reset). "Supported" means the value equals the reference and the citations are valid.
7. **Stages and gates.** S0 scripted (192 rows, 0 calls), P0 one-call probe, Q0 (23 calls), S1 (576 calls). Batches `s0-001`, `p0-001`, `q0-001`, `s1-001`. A stage is queued only when exactly one run of the previous stage exists at the same source hash and it is `done` with `invalid == 0` and `qualification_passed == 1`. A batch name is never reused.
8. **S0 acceptance.** All 192 rows valid; the reference answer equals the hand-written table in every row; both qualification sets pass their gate under the reference; invariants: (a) the content packet of the false-original state contains the false original record with F and contains T nowhere; (b) no message of the misquote and stale states under raw and metadata, of the copies and false-original states under any policy, or of any state under reset contains T or T + delta as a number; (c) no message or system prompt contains a state name, a policy name or an evaluator field; (d) within a root and state, `task` and `inherited_memory` are identical across raw, metadata and content, the registry is identical across metadata and content, and reset is empty; (e) within a root, the requested fact, delta and the three other notes are identical across states and `min_origins` is 2 only in copies; (f) 8 roots per family, 24 assignments per root, 576 distinct assignment ids; (g) every request is at most 16,000 bytes; (h) retrieval counts and bytes regenerate identically; (i) the two qualification sets, the engineering roots and the S1 roots are pairwise disjoint; (j) the registry of a message lists exactly the cited records, and the retrieved records are exactly the cited records plus the current version of a superseded one, each equal to the source store's own record; (k) scripted control actors score as designed: the reference actor −0.5 on the primary and 1.0 on clean completion for raw, metadata and content; an actor that always repeats the note 0.0 on the primary; an actor that ignores versions −1.0; an actor that always abstains 0.0 on the primary and 0.0 on clean completion; an actor that answers another fact is graded unsupported. Item (k) is the check that the design is not at floor or ceiling by construction: the same instrument returns −1, −0.5 and 0 for three different successors.
9. **P0 acceptance.** One call: qualification fixture 0 of set a. Passes when the response parses, the model slug is `qwen/qwen3.7-flash` or its dated form, the response names its serving provider and it is Alibaba, usage is reported, the finish reason is `stop`, no reasoning tokens are reported and the answer has valid structure. Its summary and hub record carry the raw response metadata of the call: response model, provider, response id, finish reason, reasoning tokens, latency, provider-reported cost, tokens and tokens per byte. Agreement with the reference is judged in the Q0 gate, over all 24 rows.
10. **Q0 acceptance.** Fixtures 1 to 23 of set a. Set a is six roots (5501 to 5506, two per family), one memory state per root, four policies each. The gate reads P0's saved row and Q0's 23 rows: 24 of 24 valid structure and 24 of 24 supported (value equals the reference, citations valid), including every null. Thresholds are never lowered. A failed Q0 stops the chain. The one permitted repair is attempt 002 on set b (roots 5601 to 5606, a different pairing of states with roots and families), with a new source hash and its own pre-run review, after the failing answers have been read; a failed repeat ends the line.
11. **Actor.** `qwen/qwen3.7-flash` through OpenRouter; body keys exactly `model`, `provider` (`only: [alibaba]`, `allow_fallbacks: false`, `require_parameters: true`), `reasoning` (`enabled: false`), `max_tokens` (1,000), `response_format` (`json_object`), `messages`. No other model, no fallback. Answers are validated locally, on structure only: keys exactly `value` and `sources`; `value` an integer of magnitude at most 10,000 or null; `sources` a list of at most 16 distinct non-empty strings; duplicate JSON keys rejected. Whether the cited IDs exist in the message and whether they support the value is scored (citation validity, support), so an unsupported or badly cited answer is a measured outcome and not a failed call. An answer of invalid structure is a failed call; there is no repair call and no answer is ever retried.
12. **Transport retry rule.** At most 2 retries per call, only for HTTP 429 and the overload statuses 502, 503 and 529 (the provider rejected the request before the model ran), backoff 2 s then 6 s, `retry-after` honoured up to 20 s, all inside the one 120 s request timeout. Timeouts, other statuses, refusals and invalid or wrong answers are never retried. One reservation per call, at 10 times the byte-based bound (input tokens at most the bytes of the encoded request, plus the full output limit, at the frozen prices); every HTTP attempt is recorded in the ledger before it is sent, with a study cap of 800 attempts.
13. **Failure handling (rule of 2026-10-04).** Part 1 adopted: a failed HTTP request keeps its status, the first 2,000 characters of the response body and the request id; request headers and the key are never stored. Part 2 does not apply: this route has no token-counting request; the reservation is a byte-based upper bound. Part 3 adopted: in S1 a call without a valid answer is recorded as failed with its evidence and dispatch continues until failed calls exceed `max_failed` = 6 (the larger of 3 and 1% of 576, rounded up); integrity failures (a ledger refusal, a breached reservation, a model mismatch, a missing or wrong provider name, a response above the 8,000-token input ceiling, a request above the size limit, a packet that no longer equals its manifest hash, a source or batch mismatch, a deadline, an internal error) stop dispatch at once; a call not dispatched because of the deadline is recorded as not started; S1 ends `done` when failed calls are within the limit and `failed` otherwise; S0, P0 and Q0 stay strict. Part 4 adopted: a billing or limit refusal (HTTP 402, or a 400, 403 or 429 whose body names credit, balance, billing, a usage or spend limit, an exceeded limit or insufficient funds) pauses the whole stage, the same call is re-sent every 60 s for up to 1,200 s, nothing is recorded as a model outcome meanwhile, and the pause is reported (`billing_pauses`, `billing_pause_seconds`, `billing_affected_calls`); if the outage outlasts the limit the stage stops with `provider_credit_balance_low`, the affected and unfinished calls are recorded as not started, the reservation of each affected call is voided in the ledger (no model ran), and nothing counts toward `max_failed`.
14. **Resume after a billing stop (pre-registered).** Units left not started by a `provider_credit_balance_low` stop of S1 may be resumed at the same source hash, as a dated amendment recorded in this folder, because a billing outage is unrelated to outcomes. `python src/chain.py resume` queues a continuation batch `s1-001-r1` (then `-r2`, ...) holding exactly the not-started units, under the same ledger and caps: the continuation shares the call allowance of the batch it continues, so answered plus open S1 calls never exceed 576. It refuses after any other kind of stop. The analysis reads the original run and its continuations together and counts every unit once.
15. **Execution limits.** Four requests in flight; 120 s per request; 6,000 s per stage; 7,800 s for the chain (S0 under 60 s, P0 at most 120 s, Q0 at most 23 × 120 / 4 = 690 s, S1 at most 6,000 s: 576 calls at an expected 3 s with four in flight is about 430 s, the limit allows a mean of 30 s per call plus one full 1,200 s billing pause). Ledger caps per batch: P0 1 call, Q0 23, S1 576 (600 for this attempt); the ledger's study-wide cap is 624 because the one permitted repair attempt's 24 qualification calls (`p0-002`, `q0-002`) would use the same ledger; USD 2 of settled cost plus open reservations. Cost arithmetic at the frozen prices (USD 0.03 per million input tokens, USD 0.13 per million output tokens): expected 600 calls × (about 1,500 input tokens × 0.03 + about 40 output tokens × 0.13) / 1,000,000 = about USD 0.03; worst realistic, every request at the 16,000-byte size limit counted at one token per byte and the full 1,000-token output limit: 600 × (16,000 × 0.03 + 1,000 × 0.13) / 1,000,000 = USD 0.366. Both are far inside the cap. Open reservations: the largest built request is 5,068 bytes, so one reservation is at most 10 × (5,068 × 0.03 + 1,000 × 0.13) / 1,000,000 = USD 0.0028; at most 4 are open at once (USD 0.011), and a failed call without reported usage keeps its reservation (at most 6 + 4 such calls, USD 0.028). Input ceiling: every request is at most 16,000 bytes, which is at most 6,400 tokens at the assumed worst case of 2.5 characters per token; the actual requests are several times smaller. Before S1 the chain stops with `input_ceiling_projection` if the largest measured tokens per byte in the qualification rows (P0's row included) times the largest S1 request exceeds 8,000 tokens, and with `projection_exceeds_cap` if 576 × the measured mean cost per call exceeds what is left of the cap.
16. **Analysis.** All 24 roots are retained in every analysis. If every primary cell is observed: the mean of the 24 root values `d_r`, all 24 values listed, and a 95% interval from 10,000 bootstrap draws over whole roots, seed 20261004. Missing-data rule: every failed or not-started unit stays in its cell's denominator with outcome bounds 0 and 1; contrasts are reported as bounds over all 24 assigned roots plus the complete-case estimate with its denominator; nothing is dropped, imputed or re-run. Per cell (6 states × 4 policies, 24 roots each): correct, abstain, inherited error, other wrong, supported, supported-and-wrong, unsupported-and-correct, unsupported-and-wrong, unnecessary abstention, valid citations. Reported separately and never pooled into the primary: contradiction (abstention), copies, false originals (source-supported answers against hidden-truth correctness), and reset (cost of forgetting: clean completion under raw minus under reset). Identical packets in different cells are counted and reported; they are not extra worlds. No multiplicity-adjusted or confirmatory claim.
17. **Retrieval log.** Each row records the protocol's deterministic retrieval: registry lookups, records retrieved, bytes added to the message, and the measured time of the lookup. Totals per policy are in the summary and on the hub. No paid retrieval and no model judge are used.
18. **Stop rules.** No answer retries, no replacement runs, no change of sample, thresholds, states or policies after outcomes are seen. Null and adverse results complete the study. S2 stays closed. All root ids stay below 10000.
19. **Scope.** One fresh successor and one handoff per assignment. This establishes at most one-handoff behaviour on one synthetic task and one model configuration; it is not a multi-generation or culture result and not a full turnover crew.
20. **Review status and authority.** As relayed to this builder by dmarz/pipeline on 2026-10-04: dmarz directed this program himself (research program v5, written with him by a Codex session on 2026-10-04; his instruction to ship it was relayed by dmarz/fleet-monitor). The design is the program's; this package implements line M as specified there. Cross-researcher review is waived by dmarz for these exploratory runs; dmarz/fleet-monitor's check is a same-researcher check and nothing more; the run is not independently reviewed. Cost is not the gate, but every run has hard `max_calls` and reports actual calls, tokens and dollars to the hub. The run is launched only by the orchestrator from the private run queue. Implementation note of the same date: the program's five-session and shared-reservation arrangement is replaced by the ready-chain (one package per line, one server per line, its own ledger and caps).

## Changes after the first version of this file, all on 2026-10-04 and before any run

The first version (commit `bee94550`) was committed before any code existed. These changes were made while the package was built; the items above state the current rule.

- **Validation is structural (item 11).** The first version also required cited IDs to appear in the message and `sources` to be empty exactly when `value` is null. That would have turned a behaviour (answering without evidence, for example under reset) into failed calls counted against the limit of 6. Those properties are now scored instead: citation validity and support. Changed by the builder before any code was pinned.
- **Adapter revision (items 9, 12, 13, 14, 15).** `src/provider.py` is the reference adapter of dmarz/pipeline at main `639e9501`, unchanged: a response must name its provider and it must be Alibaba; reservations carry a 10 times margin; a call left unanswered by a billing stop has its reservation voided, so a continuation runs inside the exact S1 cap; the billing detector also covers 429 and names billing, usage or spend limits; call caps are counted per batch family and the study-wide ledger cap is 624. Required by dmarz/pipeline after the fleet monitor's standby reviews.
- **Probe metadata (item 9).** P0's summary and hub record carry the raw response metadata. Required by dmarz/pipeline for every program v5 package.
- **Integrity stops (item 13).** The list now names the provider checks, the input ceiling, the size limit and the packet hash check; a call not dispatched because of the stage or chain deadline is recorded as not started, not as failed.
- **Invariants (item 8).** Item (j) added: exact registry and retrieval contents. 25 checks run in S0 and in the selftest.
- **Input-ceiling projection (item 15).** The chain uses the largest tokens per byte over all 24 qualification rows (P0's row included), which is at least P0's own value.

The comparison, the states, the policies, the reference table, the roots, the qualification rule and the analysis (items 1 to 7, 10, 16 to 19) have not changed.
