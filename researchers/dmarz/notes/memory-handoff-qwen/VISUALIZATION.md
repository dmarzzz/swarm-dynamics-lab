# Visualization mapping v1: memory-handoff-qwen

- Mapping version: v1, bound to the source hash in [READY.yaml](READY.yaml). Renderers: `src/render.py` (frames and GIF, Pillow only) and `src/journal.py` (the replay page). No parent mapping; the layout is specific to this study.
- Run bindings: each stage is one hub run of experiment `memory-handoff-qwen` with params `stage`, `batch` (`s0-001`, `p0-001`, `q0-001`, `s1-001`, and `s1-001-r<n>` for a continuation), `source_hash` and `code`. Each row binds root, family, memory state, handoff policy and, for qualification fixtures, the fixture number.
- Behaviour to show: for each memory state, what a successor does with the same inherited notes under each handoff policy: repeats the inherited error, abstains, or answers correctly; and for single assignments the path from the source records through the predecessor's note and the handoff to the successor's answer.
- Status: both renderers are implemented and tested offline on scripted rows. No frame of a paid stage exists, because nothing has run.

| Recorded signal / exact field | Unit, denominator or derivation | Visual encoding | Actor-visible or evaluator-only | Missing / failure display |
|---|---|---|---|---|
| row `evaluation.outcome` | one of correct, abstain, inherited error, other wrong, per assignment | one square per assignment in a 6 × 4 grid (rows: memory states; columns: handoff policies), up to 24 squares per cell ordered by root; blue correct, grey null, red-orange inherited error, purple other wrong | evaluator-only (grading uses hidden truth) | failed call: white square with a cross; not started: empty outline |
| row `evaluation.supported` | value equals the reference and citations valid | dark underline below the square | evaluator-only | no underline on failed and not-started squares |
| primary contrast (`analysis.primary`) | inherited error under content minus metadata, mean of misquote and stale within root; complete-case estimate, complete roots, all-assigned bounds | text block at the right of the final S1 frame | evaluator-only | bounds are shown whenever a primary cell is missing; never a zero |
| clean-memory correct completion (`analysis.utility_guard`) | correct / observed in the clean row, per policy | text block at the right of the final S1 frame; the clean row of the grid | evaluator-only | observed count shown as the denominator |
| gate (`qualification_passed`) | 1, 0 or none | text at the right of the S0, P0 and Q0 final frames | evaluator-only | "FAILED" in words |
| source-to-successor trace of the latest row (`packet_summary`, `answer`, `reference`) | what the source store holds for the requested fact, what the note claims, what the handoff added (registry entries, records, bytes), the answer, the reference, the hidden-truth answer, the outcome | five text lines under the grid | evaluator-only | "no outcome" with the failure category |
| stage and study accounting | answered rows, rows without a valid answer, ledger calls and actual dollars, seconds since stage start | header line | none | zero until the first call |
| per-assignment replay (`replay.html`) | five steps per assignment: sources (evaluator view), predecessor notes, handoff (registry entries, retrieved records, lookups, bytes, lookup time), successor answer, score | a self-contained page with an assignment selector, a five-position slider and Previous, Next and Play | evaluator-only; model strings are written as text, never as HTML | failed and not-started assignments say that the outcome is unknown and bounded |
| retrieval log (`retrieval`) | registry lookups, records retrieved, bytes added, measured lookup seconds | step 3 of the replay page; totals per policy in `analysis.json` | evaluator-only | zero for raw and reset by construction |

- Time axis: completion order of calls, from 0 to the stage's assignment count. It is not interaction time: every call is one independent successor with no memory of other calls. Wall-clock seconds since stage start are in the header.
- Event markers: none inside a stage. Stage boundaries are separate runs with their own frames. A continuation's frames show the earlier runs' rows and its own together.
- Cadence and bounds: `initial_frame.png` before the first call; `progress.png` at most every 20 s and once when the stage stops; `final_frame.png`; `replay.gif` with at most 25 frames (the empty frame plus prefixes at 24 equal steps of the recorded rows), 500 ms per frame and 2.5 s on the last. Images are 1420 × 800. The S1 replay page is about 1.5 MB.
- History for replay: `episodes.jsonl.gz` in completion order, `assignments.jsonl.gz` (every message and its evaluator labels), `events.jsonl.gz` (the hash-chained journal: handoff, call start, response or failure, terminal) and `analysis.json`. Every frame and the page can be rebuilt from these without a model call.
- Destination: PNG, GIF and HTML artifacts of the hub run. No custom player is assumed on the hub; the PNG is the static fallback and the page is opened from the downloaded artifact.
- Public-safe fields: frames and the page contain fictional records, answers and aggregates. No credential, address or request header appears. Successor messages never contain the evaluator-only fields; S0 invariants and a wire-level selftest check that.
- Honesty rules: scripted stages say "SCRIPTED - NOT MODEL EVIDENCE" in the frame header and on the page. A failed or not-started assignment is drawn as such and never as an abstention. No model call is made for rendering; rendering reads no random stream.
- Synthetic-trace validation (selftest `test_frames_replay_and_page_render_for_empty_partial_failed_and_final_states`): empty, partial and final frames with a failed and a not-started row; a GIF whose frames are all decoded; a page built from rows whose model string contains markup, which must not appear as markup.
- Acceptance checks after a run: the initial frame shows 0 answered; final frame counts equal `summary.json`; the squares of a cell equal that cell's counts in `analysis.json`; the primary line equals `analysis.json` `primary`; the page opens and steps through an assignment; `chain.py verify` confirms artifact checksums.
- Rendering failure policy: a failed frame, GIF or page is recorded in `summary.json` `reporting_errors` and does not stop calls or change a row. A missing final artifact makes `verify` fail its artifact check; the saved rows stay intact and the frames can be rebuilt offline.
- Post-run artifact owner: the operator of the chain and dmarz/pipeline.
