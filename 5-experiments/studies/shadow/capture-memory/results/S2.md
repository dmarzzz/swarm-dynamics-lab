# S2 pilot: one real model on the capture-memory question

**Status: pilot on a labelled hunch.** Hypothesis `shadow-capture-memory` is on main with status `proposed`, not
accepted; this is the costed S2 pilot from `design.yaml -> stages.S2_pilot`, run on Shadow's GO (2026-10-04
03:30Z) with dev tasks only. It is not the holdout S2 of an accepted hypothesis. Twelve episodes on six tasks
cannot give a tight interval on anything; every CI below is a percentile bootstrap over six task clusters and is
wide by construction. Full tables: [S2_pilot.md](S2_pilot.md), [S2_pilot_cells.csv](S2_pilot_cells.csv), per-episode
records on the hub (`capture-memory`, runs tagged `S2_pilot`, `analysis-S2_pilot` carries these files).

## Setup, as run

- Model: `meta-llama/llama-3.1-8b-instruct` through OpenRouter (cheapest provider routing: DeepInfra / Novita,
  0.02 USD per M input), temperature 0.7, 8 output tokens, prompt = the two allowed names plus the names the
  agent's last L partners used (`src/model.py`). No pull h in the prompt; the label prior is the model's own.
- Design: N = 12, entrench 10, takeover cap 120, recovery 50, scored at round 50. W1_INSIDE word pairs. Memory 1
  at dose 0.42 (k = 5 of 12) and full memory at dose 0.54 (k = 6 of 12): the scripted dose-rule values carried
  over, because the model-side dose sweep from preregistration section 10 has not been run. Arms A0_no_purge and
  A1_purge, forked from one shared prefix per episode (new in commit `6e116dce`). Tasks 0 to 5, seed 1.
- Caps: 5 USD and 26,000 calls, split over four workers (1.25 USD / 6,500 calls each) so the sum cannot pass the
  cap without a shared ledger. Enforced in `src/model.py` by reservation before each request and by actual
  provider usage after it. Neither cap was approached.
- Where: shadow's own box (shad0wbot), hub queue. sim-shadow refused ssh on port 22 at 03:50Z and every other fleet
  server was under an exclusive claim, so no agentops claim was held.

after the re-ask: call-level clean-parse rate 0.993. 0 transport failures, 0 calls with missing usage.

## Against the scripted prediction

The brief's prediction, "return at memory 1, freeze at full", comes from S1b at N = 24 with 20 entrench rounds. Run
at the pilot's own configuration (N = 12, entrench 10, same doses, same tasks; `src/pilot_reference.py`,
[S2_pilot_scripted_reference.md](S2_pilot_scripted_reference.md) and the 200-episode version
[S2_pilot_scripted_reference_0-99.md](S2_pilot_scripted_reference_0-99.md)), the scripted rule predicts something
weaker:

| | scripted, 6 tasks | scripted, 200 episodes | **model, 6 tasks** |
|---|---|---|---|
| memory 1 captured / latency | 6/6, 3.5 | 200/200, 3 | 4/6, 3 |
| full captured / latency | 5/6, 96 | 176/200, 83 | 5/6, **8** |
| memory 1 A1 frac_T / delta | 0.238 / +0.190 | 0.283 / +0.241 | 0.214 / +0.179 |
| full A1 frac_T / delta | 0.300 / +0.167 | 0.278 / +0.166 [+0.13, +0.20] | 0.167 / +0.133 [-0.03, +0.30] |
| memory 1 A0 frac_T | 0.000 | 0.029 | 0.107 |
| full A0 frac_T | 0.200 | 0.154 | 0.133 |

Three things stand out, none of them a confirmation and none a refutation:

1. **Memory 1 behaves like the scripted rule.** Capture in about 3 rounds, then a partial drift back after the purge
   (+0.18 against +0.19 to +0.24 scripted), no full recovery within 50 rounds. The same "returns slowly" regime.
2. **Full memory does not behave like a running mean for this model.** The scripted full-memory agent takes 80 to
   100 rounds to tip at k = 6; the model tips in a median of 8. Whatever llama-3.1-8b does with a list of 30 to 100
   names, it is not averaging them: it weights the recent tail. At N = 12 the scripted rule itself no longer freezes
   after capture (delta +0.17, because the banked history is only ~10 rounds deep), so the freeze endpoint from S1b
   is a property of long entrenchment, not of unbounded memory as such. The pilot cannot test the freeze at all at
   this configuration; a test needs a longer entrench phase, which multiplies prompt length and cost.
3. **The label prior is real and task-specific.** Two of six word pairs did not capture at memory 1 (pira over brisk,
   olam over quon: 0.57 and 0.86 still on the original at the cap), and pira/brisk did not capture at full memory
   either. The scripted rule captures 100% of these tasks. This is the yang-2026-when artefact the pre-run named as
   the plausible negative: for some pairs the model's string preference outweighs five committed partners. Any real
   S2 has to fit (beta, h) per pair first (preregistration section 7) and either balance or exclude strong-prior pairs.

Honest summary: the model reproduces the memory-1 regime of the scripted rule, shows no evidence of a full-memory
freeze (and the scripted rule predicts none at this N), and shows a word-prior effect that the scripted rule has no
place for. The memory contrast is undetermined at this size and will stay so until the doses are fitted on the
model and the pair priors are handled.

## Cost, actual

From the provider's `usage` fields on every call (OpenRouter `usage.cost`):

| stage | calls | prompt tokens | completion tokens | USD |
|---|---|---|---|---|
| Q0 attempt 0 (local, strict parser) | 36 | 2,980 | 112 | 0.00007 |
| word-pair probe | 60 | ~5,000 | ~180 | 0.00015 |
| Q0 attempt 1 (local) | 153 | 13,252 | 498 | 0.00028 |
| Q0 on the hub | 161 | 13,882 | 515 | 0.00030 |
| **S2_pilot (12 episodes, 24 arm records)** | **10,384** | **1,462,424** | **33,994** | **0.0308** |
| total | 10,794 | ~1.50M | ~35K | **0.032** |

Mean prompt 141 tokens per call. The README estimate was 15K calls / 2.2M input tokens / 0.05 to 0.45 USD; the
prefix fork saved about a third of the calls and the cheapest routed provider was at the bottom of the price band.
Caps used: 0.6% of the 5 USD, 40% of the 26,000 calls. Wall time: about 11 minutes with four workers, each round's
decisions issued in parallel.
