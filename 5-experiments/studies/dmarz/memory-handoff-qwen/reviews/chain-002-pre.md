## Validation decided in advance (preregistration A5)

| Form of the answer text | Treatment | Counted as |
|---|---|---|
| One JSON object with `value` (integer or null) and `sources` (list of strings) | valid | |
| `value` as `45.0` or as `"45"` | valid, read as 45 | `value_as_float`, `value_as_string` |
| repeated IDs in `sources` | valid, duplicates removed | `duplicate_sources` |
| `sources` null | valid, read as empty | `sources_null` |
| working fields missing, partial or oddly typed | valid | `work_malformed`, `work_missing` |
| extra keys | valid | `extra_keys` |
| working fields after `value`, or any other key order | valid | `work_before_value` 0 or 1 (order-preserving parse) |
| `current` written as `"true"` or `"false"` | valid | `current_as_string` |
| unknown IDs in `sources`; sources given with a null value; a value without sources | valid, scored (citation invalid, unsupported) | scorer |
| text that is not one JSON object (text around it, a code fence, an array, two objects, cut-off JSON) | failed call | `invalid_json` or `invalid_answer` |
| `value` or `sources` missing | failed call | `invalid_answer` |
| `value` a boolean, a fraction, a word, a list | failed call | `invalid_answer` |
| `sources` a string, or a list with a non-string | failed call | `invalid_answer` |
| a repeated key anywhere in the object | failed call | `invalid_json` |
| longer than 4,000 characters, or cut off at 1,000 output tokens | failed call | `answer_too_long`, `truncated_output` |

One addition to the lead's list, made by the builder on the same principle: `sources` null is tolerated (a harmless way to write "no sources"). One point where the adapter decides: a repeated key anywhere in the object is invalid, not only a repeated `value` or `sources`, because the unchanged reference adapter parses strictly. The attempt-001 limits on the magnitude of `value` and on the number and length of `sources` are removed. Selftests: `test_tolerated_variants_pass_and_invalid_forms_fail` (10 tolerated variants and 29 invalid texts at the decoder), `test_through_the_adapter_tolerated_variants_are_valid_calls_and_invalid_forms_are_failed_calls` (the same through the adapter, with the failure categories), and the rehearsal's full chain, whose stub writes all 600 answers in a rotating mix of the tolerated variants.
