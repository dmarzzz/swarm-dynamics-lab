# B3 frozen scoring and case acceptance

This packet is an authored development benchmark. Its 24 worlds share eight templates and one author. Two blocks are fresh repeated executions, not additional independent scenario families. There is no AI Village data or untouched natural-data holdout in this packet.

## Endpoints and baseline

The main endpoint is the reader's YES/NO/UNKNOWN answer to the frozen follow-up question. Each question has exactly one authoritative witness record and explicit temporal/scope context. YES means supported, NO explicitly contradicted, UNKNOWN unresolved. An unavailable receipt or absent result never implies denial or failure. Gold is tied by hash to the frozen packet and kept out of actor requests. Writer release decisions concern the staging slot, are balanced independently of follow-up answer class, and are never reader fields. Raw handoff prose is preserved, including any old answer in that prose.

Report each block and policy separately, all assigned denominators, valid accuracy, all-assigned lower/upper accuracy bounds for missing/invalid outputs, and false certainty on UNKNOWN roots. A valid but wrong answer remains in the chain endpoint and does not trigger a retry or early success-based stop. A schema/route/accounting failure stops scheduling; already-started concurrent calls may complete. Missing descendants are never fabricated as errors or successes. Report paired R minus P correctness per root/block and fresh-block disagreement; do not pool hops as samples or manufacture a population confidence interval.

R is source-available plus the generated handoff, not an isolated direct-source singleton. Its family/block competence screen of80% means3/3 on this small cell; report the counts and label this a coarse descriptive screen. A deficient family restricts policy interpretation but is never removed from aggregate outcomes. The deterministic source-grammar controller and full-copy transmission are strong offline controls: both must answer every original, answer-changing mutation and answer-preserving record permutation correctly. They are not evidence of native language-model competence. Native source-available performance is unmeasured until execution.

## Bounded semantic audit

After deterministic scoring, partition valid reader outputs by eight families and correct/incorrect status. In each of these16 cells select the two smallest SHA256 values of `B3-audit-v1:<assignment-id>`; empty cells contribute no rows. This gives at most32 outputs, with no discretionary selection by interesting content. Record answer rationale support, whether the needed source fact survived the final handoff, any unsupported certainty, exact source and response spans, and ambiguity. Audit every technical failure separately. Do not claim all writer prose was semantically annotated or that the same operator's review is independent validation. A supported final answer can be correct with a flawed explanation; retain both labels separately.

## Case-quality acceptance

| Criterion | Offline evidence / limitation |
|---|---|
| Relevance | Version, restoration, provenance, check status, rollback, consent, permission and exception scope are operational distinctions that colleagues need after handoffs. Fictional framing is not validation on real incidents. |
| Answerability | Explicit affirmative, negative or unresolved authoritative witness; all evidence available to the initial writer and source-access policy. Later P omissions are the measured intervention, not hidden gold. |
| Labels | Witness IDs/spans, independently specified source controller and24 answer-changing mutations agree. Same author limits independence. |
| Isolation | Request tests prohibit evaluator fields; questions absent from writer payloads; reader receives previous prose only, without the prior decision field. |
| Challenge | Correction, limited test scope, proposed versus actual action and unavailable evidence coexist with the target observation. Only one target question is asked per world; actual difficulty is not claimed before native collection. |
| Controls | Source grammar, full-copy fit, record permutation and answer-changing mutation; R native competence screen remains pending. Source access uses additional information/input cost. |
| Holdouts | All24 worlds are inspected development material frozen before outputs. No untouched holdout or broad generalization claim. |

Case readiness is separate from route qualification, launch admission and scientific success. If both policies remain at ceiling, report the useful null rather than automatically making the cases harder.


## Prospective context-loss and implication annotation

Before native collection, classify the fixed semantic audit by provenance (origin/receipt identity), temporal/version qualification, uncertainty (missing versus negative evidence), dependencies (shared acquisition or conjunctive requirements), and conditional constraints (scope and prerequisites). For each selected final handoff, compare with the original source and label each applicable category retained, lost, ambiguous or not applicable, quoting source and handoff spans. These are semantic annotations on the bounded sample, not automatically inferred from an incorrect answer. One handoff may have multiple losses.

Distinguish a correct final answer with damaged context from an incorrect answer with retained context. Report unsupported affirmative answers on NO roots, false certainty on UNKNOWN roots, and missed supported affirmatives (NO on YES roots) separately. These last errors may block a legitimate action only where the frozen question and evidence actually imply that action; report that as a stated-decision implication, never an observed action. Audit any explicit unsafe recommendation/commitment in the reader explanation against the source; do not call a wrong answer an executed action. This task measures answer and stated-commitment implications, not real tool execution, deployment harm or a causal mediation effect. Preserve ambiguous labels and all deficient families. No new cases, calls, actor fields or decision-based stopping are introduced by this annotation clarification.
