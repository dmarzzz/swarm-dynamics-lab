# A skeptical review that can change a decision

Read the current candidate and acknowledge the controls it already contains. Use the [evidence context](CONTEXT.md) and [experimental context](EXPERIMENTS.md), then ask:

1. What observable outcome would count against the proposed explanation? Could an equally simple explanation produce the same trace?
2. Does a paper already implement this mechanism or test its failure boundary? Have we checked methods/code, or only its abstract?
3. Does the task require coordination, memory, dissent or detection? Could a single solver, lookup, fixed script or ordinary database rule solve it?
4. What changed besides the advertised intervention: information, compute, reviewer quality, source authority, timing or task difficulty?
5. Can the policy see a field that only the evaluator should know? Is a “realistic” policy quietly using oracle lineage or a completeness certificate unavailable in deployment?
6. Is the unit of inference a world, episode, seed, team or agent? Does the proposed interval respect shared checkpoints and repeated use of the same task?
7. What happens to invalid runs, correct minorities, benign updates, ambiguous cases and legitimately repeated actions?
8. Which operating assumption fails first after a new task family, weaker monitor, incomplete provenance, an adaptive input or a tighter budget?
9. Is a strong baseline win allowed to end the project? What specific result changes the implementation choice?
10. Would the proposed visualization show correctness, cost and uncertainty, or make agreement and motion look like progress?

Record a useful strength, the strongest concrete objection, its evidence status, a minimal revision, and a stopping or narrowing rule. “More testing needed” is not an actionable critique. Do not manufacture objections merely to make every card sound flawed.

## Editorial dispositions

- **retain-narrow:** worth a bounded comparison; retain the specified limitation.
- **revise:** change the comparison or measurement before drawing the proposed conclusion.
- **reframe:** useful work, but its defensible contribution differs from the headline framing.
- **merge:** an existing candidate can own the experiment; preserve the extension ID as an ablation or implementation note.
- **fix-first:** resolve a logical or measurement prerequisite before a model experiment.
- **defer:** an important dependency is not ready for the intended time budget.

These are editorial recommendations, not formal survey/hypothesis verdicts or instructions to other researchers. A concern is not a refutation. State what evidence would resolve it, and keep the original proposal intact until its owner adopts a change.
