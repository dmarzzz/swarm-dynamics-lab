# Selective preservation: decision process and comparator contract

Prospective development specification, 2026-10-04. This defines a future turnover study, not an expansion of approved A2. First qualify acquisition. The intended useful question is whether fresh members preserve supported practices, correct practices contradicted by new evidence, and avoid replacing unaffected knowledge. High retention alone is not success.

## Who decides and from what evidence

Experimental agents make the substantive decisions. The operator freezes the decision rules and available observations before collection; the scorer alone sees latent truth. Represent each inherited practice as scope/class, proposed governing source, version/epoch, and supporting observation IDs. Never include evaluator labels like valid/obsolete in actor notes. All arms receive identical environmental observations and access to the same evidence-check tool.

At a declared review checkpoint, each arm proposes one state per practice:

1. **Retain:** current-epoch observations uniquely support the inherited source, with distinguishing citations. Old provenance is context, not current validation.
2. **Revise:** current observations uniquely support a different source; cite the counterexample to the inherited source and the distinguishing evidence for its replacement. Update only the supported scope. Preserve the previous version and reason in the audit trail.
3. **Quarantine:** current evidence contradicts the inherited source but does not identify a replacement, or the current record is internally inconsistent. Do not promote an unsupported replacement or erase unaffected practices. Abstain on that scope and request the next allowed check, charging it to the common budget.
4. **Provisional:** evidence does not distinguish alternatives and does not falsify the inherited source. Keep the note visibly unvalidated, but do not count its actions as evidence-backed preservation. Use the same prespecified abstention/check policy in every arm.

Require exact evidence IDs and recompute semantic support. An independent deterministic enumerator provides the reference for what can be inferred from visible records; it is never injected into native actors. A single observation is decisive only if it logically excludes all alternatives under the declared rule family. A change in epoch is observable; which source changed is hidden. If epochs/change announcements are removed in a later realism test, that is a different detection problem requiring a separately specified window/noise model.

## Feasible development cases before any native turnover proposal

Construct three controlled cases from the existing task family: (a) stable practices with answer-preserving irrelevant-field changes; (b) one changed class with answer-changing source evidence while the other class is stable; (c) contradictory current evidence requiring quarantine, plus an underdetermined subset requiring provisional status. Old and current records remain available with epochs. Validate labels by exhaustive source enumeration and ensure each changed practice has an actor-visible counterexample. These are inspected development fixtures, not held-out evaluation or model results. A future native panel must use fresh roots and separately varied task contexts before claiming transfer beyond Boolean rules.

## Strong single-controller comparator

Use one controller with the same pinned model, same initial acquired checkpoint, same aggregate visible observations and chronological feedback, same 2400-character inherited archive, same evidence-check API/actions, identical cumulative input/output token and call limits, and the same wall-clock ceiling as the entire swarm. Private scratch capacity, if available to swarm members, must also be available in aggregate to the controller and charged identically. Fresh controller context at the same turnover checkpoints prevents its hidden conversation history from becoming an extra memory channel.

For each decision cycle, permit the controller the same number of sequential calls as the swarm has member/merge calls. It may draft, challenge its own proposal and finalize, with an explicit instruction to consider conflicting evidence and protect unaffected practices. This intentionally strong simple alternative tests whether organization helps beyond repeated checking. Account for all swarm coordinator, synthesis and repair calls; no free critic or oracle. Match maximum resources and report actual consumption/latency; native scheduling differences remain part of the architecture contrast. Develop and qualify both architectures on the same separate development panel before freezing prompts. Do not weaken a qualified controller to manufacture swarm advantage.

Add frozen-note and no-inheritance controls to identify memory contribution, and a retained-member condition to identify replacement effects. A true-policy oracle is a ceiling, not the matched controller. These controls have different roles; one comparison cannot support all claims.

## Endpoints and decision boundaries

Measure correct stable decisions, correct changed decisions, false harmful actions, useful actions retained, justified abstentions, unsupported edits, affected/unaffected note changes, correction latency and total calls/tokens/cost. Report inherited practice state and downstream behavior separately. Repeated calls/agents are nested within independent worlds. Define prospective stable-retention noninferiority margin and changed-policy benefit threshold on development data and practical costs before freezing a native proposal; this document does not invent a population effect size from six roots.

If the controller matches the swarm within a sufficiently precise prespecified margin, report portable memory or sufficient single-controller checking, not a collective advantage. Wide uncertainty is inconclusive, not equivalence. If every arm succeeds, broaden meaningful challenge in future development; if none can acquire or revise, stop the turnover claim and inspect the failed step. No additional native calls, machine allocation or budget are authorized by this specification.
