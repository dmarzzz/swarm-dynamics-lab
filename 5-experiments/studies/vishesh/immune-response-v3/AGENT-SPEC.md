# Agent specification and reproducibility contract

## Roles and access

A0–A6 are specialists. Each begins with the registry records assigned by the fixture. A7 is the coordinator and begins with an empty private store. All specialists receive their own retained records and the previous shared snapshot; their endorsements are admitted into the shared store before the coordinator acts. The coordinator receives its private memory, current shared records and public requested service names. Neither role sees truth, corruption labels, arm names, task IDs, checkpoint contents, or other agents' private stores. The repair controller and visual evaluator are separate oracle components.

A2 supplies a bounded scripted false record during the incident. It is not a separately prompted adaptive attacker. Q arms revoke A2's future contributions after round six; revocation does not remove already-resident shared copies. The remaining honest actors are never replaced or silently repaired except by their assigned intervention.

## Response contract

`immune.CHOICE_INSTRUCTIONS` is the exact versioned system instruction. `choice_contract()` derives an explicit JSON schema from only the visible supplied records. `choices` has exactly one property per visible fact key; its value is a supplied record ID for that same key, or null to decline/forget. This makes two simultaneous endorsed versions of one fact unrepresentable. Unknown keys/IDs fail validation. Validate the whole choice object before mutating memory; a rejected response leaves prior private memory intact and is recorded as a failure.

The coordinator additionally returns an exact-key integer-or-null service plan, exact four integer-or-null compatibility values, and mock-deploy or abstain. All numeric scoring excludes booleans. Endorsed records replace the actor's retained memory; omitted records are not hidden in conversation history. There is no provider-side conversation continuation, retrieval cache, tool access, network action, scratchpad or implicit private chat history.

## State and execution

Records contain immutable IDs, key/value, version, source and optional parent IDs. Shared ingestion takes the highest version, with deterministic last-admitted tie behavior. Returned record content is resolved from supplied immutable IDs, not generated by the model. Actor execution is ordered by seat within a round; branches execute in a task/seed-randomized order. All actors in a round see a copied previous shared snapshot; the coordinator sees the resulting current shared store. C3/C6 forks use deep copies, including history and pending state.

Native model: claude-haiku-4-5-20251001; temperature 0; max output 768 tokens; max serialized input 12,000 bytes; one request per non-revoked actor slot. No hidden retries or automatic model substitutions. Price assumptions and configuration are pinned in model-config.json. Native sampling is not guaranteed deterministic, and seed 1 is not passed to the provider. The scripted policy is an explicit highest-version preference model and is labeled non-model evidence.

## Reproduction evidence

Each manifest includes Python/model versions, source/config/protocol hashes, commit, assignments and start time. Native event logs retain sanitized synthetic observations, constrained schemas and responses; round events retain measured state counts for replay. Credentials stay outside observations and reports. Per-round journal flush/fsync and per-batch outcome fsync preserve progress; an interrupted run may have partial telemetry and must be reconciled rather than called complete. Source hashes alone do not reproduce provider sampling; archived events allow scoring/visual replay without new model calls.
