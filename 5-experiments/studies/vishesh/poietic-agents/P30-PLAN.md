## TLDR

Can 30 initially identical agents discover a useful division of labor through capability shedding, shared data services and cheaper executors? Compare adaptive A3 with a fixed 30-member swarm plus an ordinary shared cache, A1, on the same four workload roots. Measure correct fresh answers, complete API/infrastructure cost per assigned job, actual capability/model changes and redundant fetches. First qualify the two selected inexpensive interfaces on 96 fresh lifecycle decisions. Only after both pass, run six epochs of 30 jobs per arm/root: 1,440 assigned jobs. Thirty members are dependent components, not 30 independent samples. This is a synthetic feasibility study with four paired roots and two workload families, not a definitive efficiency or novelty result.

## Question and prediction

The empirical unknown is whether local, charged structural proposals produce executable differentiated roles while retaining useful task performance, and whether their acquisition cost amortizes against a strong simple cache within this horizon. A conventional cache may be cheaper and equally accurate. Uniform cheap execution or a programmed controller may explain any apparent advantage; report those limitations rather than calling any heterogeneous graph beneficial.

D0-02 established working wrapper normalization but exposed wrong answer values, incomplete nested contracts and a provider refusal. New collection is needed because saved traces cannot establish competence of different cheap executors on fresh inputs, or whether 30 persistent actors organize services without prescribed roles. We predict neither a win nor a minimum number of specialists. A null or adverse result is a valid outcome.

## Protocol

**Q30-01 qualification:** two interfaces × 12 fresh cases × four dependent decisions = 96 maximum physical calls, no retries. Require 48/48 contract-valid and at least 44/48 exact correct successfully executed actions for each interface, with no protected access. Report outer parse validity, complete payload validity, successful execution and semantic correctness separately. The first contract-invalid response stops that interface; any transport/authentication/served-route/billing/protected-access failure stops the complete stage. Valid wrong answers remain in the denominator. Do not lower thresholds or rescore old cohorts.

**P30-01 comparison, conditional on qualification:** four independent generator roots paired across A1 and A3; six epochs, 30 jobs per epoch, one balanced shuffled assignment per actor per epoch. There are 180 jobs per lineage, eight lineages and 1,440 assigned jobs. Roots are nested in two synthetic task families; infer no broad domain generality. Rotate arm order within roots. Freeze assignments and analysis before generating main payloads. Qualification and evaluation do not share roots.

Epochs 1–2 are acquisition, 3–4 stable, and 5–6 changed workload. High-overlap epochs have 24/30 repeated required occurrences, built as eight repeated requests per endpoint plus two unique requests per endpoint. Low-overlap epochs have zero repeated occurrences. Source/schema version is part of every cache/service key. The overlap-change scenario changes only repetition; schema-change retains the workload overlap and changes the documented representation. Do not combine shocks.

This pilot uses a closed-loop workload: each epoch begins after the previous jobs and boundary proposals finish. It does not reuse the old six-job, 120-second arrival schedule for 30 members. Charge all adaptation and waiting in wall time; each job has a 60-second deadline from its actual release. Report throughput and elapsed time, not a claim about externally fixed arrival-rate reliability. A three-hour comparison deadline stops remaining work explicitly; it is never extended to complete a favorable cell.

A1 retains initial executor/tools/skills and uses the existing version-aware shared cache with equal memory, evidence and tool permissions. It may execute the same generic safe programs and messages but cannot structurally mutate. A3 may make one local proposal per actor at each of the five boundaries: at most 150 proposals per lineage, 600 across the four adaptive lineages. Actual service delivery, removed tool schemas, changed prompt definitions and served model identity must demonstrate manipulation. A model label without a backend change is not differentiation. Services run deterministic data/procedure code and need no extra model call just to serve cached bytes.

Use at most six registered services and the existing per-service capacity limit of 12. The total directory/context limit is explicit for all arms; reject over-cap proposals atomically without revealing hidden utility. Preserve complete payload schemas and receipt validation. Boundary changes become effective before the next batch; proposal information contains only the actor's own past observations, delivered messages and current public advertisements. No topology optimizer or scripted role assignment creates the treatment.

Before native comparison, offline controls must demonstrate exact reference answerability, stale receipt rejection, real mask removal/restoration, real service reuse, no cross-arm memory, 30 balanced identities, correct 24/30 and 0/30 overlap, and a simple programmed controller using only public APIs. The reference is a ceiling/competitor, never an answer service for native actors. Include its fetch/operation/runtime costs and disclose its hand-authored construction; do not claim that native swarms outperform it or all-cheap static routing without a measured comparison.

Stop the entire stage for a provider/integrity/budget failure. A malformed main action ends its job; record all other assigned jobs and stop a lineage if its first completed epoch has fewer than 24/30 correct fresh answers. Do not spend on later adaptation when basic capability has collapsed. A failure of either paired arm makes the root incomplete for comparative inference; preserve all rows and report conservative missingness bounds. No retries, automatic model substitution or favorable-effect reruns.

## Metrics

Primary feasibility endpoints: correct-and-fresh answers per all assigned jobs, cost per assigned job including acquisition/proposals/uncertain calls/infrastructure, and whether permitted configuration changes execute on later jobs. Report absolute performance for each arm and paired root differences/ratios. A suggestive benefit requires at least 95% correct fresh answers in each arm, no more than a two-percentage-point A3 quality loss, and at least 20% lower A3 cost; four roots cannot establish the original confirmatory confidence-bound rule. Describe estimates and ranges; do not treat jobs, epochs, calls or agents as independent n.

Secondary: repeated fetches, cache/service hits, prompt tokens, model-call/zero-model operations, payload failures, semantic errors, stale/protected access, actor definition histories, effective service edges, executor distribution, proposal acceptance, acquisition cost and recovery after the change. Zero accepted changes is an interpretable null manipulation result. A changed graph without delivered services or useful output is not success.

Every assigned call/job receives started/terminal/accounting status. Retain effective requests, context/definition hashes, raw responses, parsed actions, transaction effects, provider identity, usage and uncertainty in the private archive. Publish aggregate tables, full-history derived topology/cost views and manifests, with unstarted outcomes visible. Replay every qualification miss and every primary outcome. Inspect aggregate figures and read back artifact hashes. Complete operational finalize and all eleven scientific quality dimensions for qualification and comparison separately.
