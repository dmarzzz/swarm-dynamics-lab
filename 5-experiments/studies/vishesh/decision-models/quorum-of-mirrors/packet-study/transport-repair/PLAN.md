# Offline error-telemetry repair after PQ-02

Prospective offline change, written before implementation. No new native attempt or retry. Preserve PQ-02 frozen runtime/results. Its HTTP400 body was discarded, preventing exact diagnosis. Add a bounded HTTP-error reader that emits only allowlisted error categories, HTTP status, byte count and body digest; never arbitrary provider text, headers, reflected payloads or credential values. Recognize schema-complexity wording internally without returning that text. Tests inject reflected fake secrets, oversized payloads, malformed JSON and nested provider metadata. Supply an integration patch against the frozen runtime, without applying it to PQ-02.

Anthropic documents HTTP400 for excessive compiled-schema complexity, including internal limits beyond its explicit16-union limit: [official documentation](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#schema-complexity-limits). PQ-02's rejected request has nine nullable facts versus seven in its successful request, both below16; complexity is a hypothesis, not a verified cause. OpenRouter documents typed error metadata: [official documentation](https://openrouter.ai/docs/api/reference/errors-and-debugging). A future request should use constant-size source/report fact arrays, validated for exact ID coverage in code, to avoid schema size changing with repetition; this wire-format change needs a new frozen manifest and admission. Do not claim offline JSON validation proves provider grammar compilation.
