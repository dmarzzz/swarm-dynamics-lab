# Bounded scenario contracts

These nineteen reusable task kits are proposed specifications. They are not nineteen implemented environments. Small means standard-library fixtures and a bounded protocol look plausible; medium adds annotation or tool/policy integration; conditional requires artifacts, faithful models or training capability already in hand. None is a measured build-time estimate. Start with one kit and one contrast.

<a id="api"></a>
## API — Choose an API or tool from conflicting evidence

**Scope:** Small

Recommend one invoice-extraction API meeting explicit accuracy, cost, latency and data-handling requirements. Agents inspect different evidence packets.

**Minimum fixture:** Three fictional providers; twelve short records across documentation, tests and third-party claims; four investigator roles; executable feasibility and utility rules. Vary provider names and which constraints bind across worlds.

**Scoring contract:** Feasible choice rate; regret relative to the best feasible provider; unsupported claims; justified abstention; acquisition and discussion cost. Truth comes from a hidden contract and test table, not vendor reputation.

**Baselines:** Single agent with the same union of available evidence and resource cap; independent vote; simple shared blackboard.

**Scope cut:** No live procurement, real credentials, changing vendor prices or unbounded browser search. Follow the existing external-influence protocol rather than creating competing rules.

**Interpretation risk:** One obvious winner or a single magic document can reduce a collective decision to trivial retrieval. Give information that can be combined, and include no-feasible-option cases.

**Workload connection:** Research synthesis and tool-use benchmark patterns; the specific API procurement fixture is our proposed adaptation.

<a id="result"></a>
## RESULT — Review and repair a shared result

**Scope:** Small

Produce an invoice summary or benchmark-result table, then detect and repair one incorrect contribution and its dependent conclusions.

**Minimum fixture:** Synthetic source records, a small derived table, two dependent aggregates, versioned notes and a correction. Start with one contamination route and a clean arm.

**Scoring contract:** Cell and aggregate correctness; residual contaminated dependencies; useful work retained; recurrence after a stale update; time and resources to recovery. Judge actions against fixtures, not an agent’s presumed intent.

**Baselines:** No response; simple validation/recompute; restart or restore with explicitly declared surviving information; targeted repair when comparing the immune design.

**Scope cut:** Use deterministic extraction/arithmetic first. Do not build a general alignment detector or open-ended autonomous defender. Reuse the immune design’s fixed primary contrast.

**Interpretation risk:** An oracle contamination label makes defense trivial; the deployed detector sees only evidence available in the condition. Benign errors and malicious changes can be behaviorally indistinguishable.

**Workload connection:** Tool-using agent reliability and adversarial task evaluation; proposed shared-artifact workflow.

<a id="research"></a>
## RESEARCH — Curate an evidence bundle for one research question

**Scope:** Medium

Select a short, supported resource bundle answering a narrow research question and explaining remaining uncertainty.

**Minimum fixture:** A frozen set of roughly twenty-four source cards with verified metadata and licensed or short excerpts; five required claims; duplicates, off-topic distractors and one contradicting result; output at most five sources. Counts are prototype planning choices.

**Scoring contract:** Supported-claim coverage; citation entailment against annotation; duplicate ancestry; precision among selected relevant resources; cost. Allow multiple equally valid bundles and report annotation disagreement.

**Baselines:** BM25/keyword shortlist plus fixed coverage rule; one agent at matched cost; independent search then merge.

**Scope cut:** Begin with a frozen corpus, not the live web. Rank coverage and support, not a subjective universal “best paper.”

**Interpretation risk:** A hand-curated answer list can favor the designer’s literature preferences. Separate factual support from graded relevance and hold out topics/source families.

**Workload connection:** Documented production multi-agent research is a direct workload precedent; this frozen-corpus benchmark is a proposed simplification.

<a id="patch"></a>
## PATCH — Review a small code patch against requirements

**Scope:** Medium

Select or repair a patch for one bounded function or small utility, then review its tests and behavior.

**Minimum fixture:** A tiny local repository with explicit behavior contracts; three candidate patches; visible tests and independent hidden edge cases. No arbitrary downloaded code execution.

**Scoring contract:** Hidden-test pass rate; regression rate; false acceptance/rejection; review time and cost; semantic contract violations. Test passing alone is a bounded proxy for correctness.

**Baselines:** Single reviewer; static/test-only gate; independent reviewers with equal total tool calls.

**Scope cut:** Do not run the full SWE-bench stack for the first demo. Use a deliberately small, auditable fixture and call it an adaptation.

**Interpretation risk:** Shared blind spots in tests can make every judge accept the wrong result. Hold out cases independently of patch generation.

**Workload connection:** SWE-bench supplies a direct coding-workload precedent, not evidence that a multi-agent review protocol wins.

<a id="handoff"></a>
## HANDOFF — Resume a workflow after correction or staff turnover

**Scope:** Small

A replacement agent continues a partially completed API comparison or result audit using inherited notes and a versioned ledger.

**Minimum fixture:** One task state, old and corrected facts, supersession links and two or three handoff generations; declare private and shared state.

**Scoring contract:** Correction retention; retrieval accessibility; later decision correctness; obsolete-rule retention; recurrence and resource cost.

**Baselines:** Append-only correction; explicit supersession; clean restart with the same permitted facts.

**Scope cut:** Use a finite episode and fixed snapshots. Avoid multi-day autonomous operation and vague culture claims.

**Interpretation risk:** Model priors or hidden source access can masquerade as memory or recovery. Record every inherited channel.

**Workload connection:** Long-running research and engineering workflows motivate handoffs; the proposed generational fixture is not evidence of cultural evolution.

<a id="support"></a>
## SUPPORT — Resolve a synthetic customer request under policy

**Scope:** Medium

A triage agent and specialists resolve a refund, order change or access request using bounded tools and explicit permissions.

**Minimum fixture:** Synthetic customers and orders, one policy document, a short action API and deterministic user messages; at most one policy conflict per initial fixture.

**Scoring contract:** Authorized task completion; incorrect refusal; unauthorized action; state consistency; turns and cost. Score end state, not a single mandatory action sequence.

**Baselines:** One agent with the same tools and cap; fixed routing and policy-rule baseline.

**Scope cut:** Text only, no payments or external communication; no open-ended user simulator initially.

**Interpretation risk:** A correct factual answer does not imply authorization to execute. An unavailable required fact should support abstention or a question.

**Workload connection:** τ-bench is direct evidence for policy-constrained customer-service evaluation; the multi-agent split is our adaptation.

<a id="batch"></a>
## BATCH — Allocate a limited budget across useful subtasks

**Scope:** Small

Divide bounded lookup, validation or enrichment jobs among workers and reserve enough capacity to finish a verified output.

**Minimum fixture:** Eight to twelve small jobs with varied known costs and marginal value; three workers; an authoritative resource ledger; decomposable and sequential variants.

**Scoring contract:** Useful verified value per resource; completion; duplicated work; idle/stranded capacity; constraint breaches and unfinished tasks.

**Baselines:** Equal split; fixed priority; one coordinator; an oracle allocation shown only as a ceiling.

**Scope cut:** One currency initially with a hard cap; add latency/context only for candidates explicitly about multiple resources.

**Interpretation risk:** Scripted policies validate accounting but not how LLMs perceive budgets. Charge negotiation, failed calls and final verification.

**Workload connection:** Parallel research resource management is documented; this controlled allocation microbenchmark is proposed.

<a id="trace"></a>
## TRACE — Reconstruct and triage an incident from partial logs

**Scope:** Small

Reconstruct who saw which evidence and which action violated a stated rule; produce a supported incident casefile.

**Minimum fixture:** Synthetic, fully generated event history plus a separately redacted view; one incident and matched benign lookalikes; evaluator retains the complete trace.

**Scoring contract:** Supported-link precision/recall; calibrated unknowns; incident detection at realistic prevalence; review effort; unsupported attribution.

**Baselines:** Simple event rules or keywords; chronological viewer; one reviewer.

**Scope cut:** No real-person attribution, private chat ingestion or general “malicious agent” classification.

**Interpretation risk:** Common tools, prompts or sources can mimic coordination. Separate observed events, inferred causal links and unknown ownership.

**Workload connection:** AgentDojo motivates concrete security properties; synthetic trace triage is an adaptation, not its benchmark score.

<a id="identity"></a>
## IDENTITY — Allocate service or votes across declared identities

**Scope:** Medium

A local service registry admits workers or allocates quota while one controller may operate several identities.

**Minimum fixture:** Known controller-to-identity ground truth, generated credentials/lineages, fixed workloads and explicit adversary capabilities; no real credentials.

**Scoring contract:** Influence or quota captured; legitimate service denied; review cost; grouping errors; violations of declared permissions.

**Baselines:** Per-identity rule; per-lineage rule; controller oracle as a ceiling; randomized allocation.

**Scope cut:** Simulate identity relations; do not implement production attestation, anonymity or anti-Sybil cryptography in a weekend.

**Interpretation risk:** A registry simulation cannot prove unique-human identity, unforgeability or deployment privacy. Similarity is not ownership.

**Workload connection:** Mechanism-test environment from the existing Sybil/fork-merge questions; production feasibility is not established by this review.

<a id="market"></a>
## MARKET — Run a tiny market for API capacity

**Scope:** Medium

Firms set prices and allocate capacity for two synthetic services under fixed demand and known ownership.

**Minimum fixture:** Two to four firms, two goods, a short fixed horizon, simple capacity costs and public/private message or ledger conditions.

**Scoring contract:** Prices, quantities, consumer welfare, profit, concentration and detection errors separately; count real owners as well as firm names.

**Baselines:** Scripted competitive policies, common-demand-shock controls and fixed ownership/capacity.

**Scope cut:** Use the existing swarm-factory small-model plan; no Factorio or live businesses initially.

**Interpretation risk:** High prices or synchronized actions alone do not prove collusion. Toy economic welfare is not a real market estimate.

**Workload connection:** Existing swarm-factory design is the direct local plan; biological commons analogies do not establish economic guarantees.

<a id="flock"></a>
## FLOCK — Navigate a small simulated group to a beacon

**Scope:** Small

Point agents navigate toward a known target through occlusion and obstacles with declared local sensing rules.

**Minimum fixture:** A deterministic two-dimensional arena, roughly twenty particles, seeded initial positions and configurable observation/noise/coupling rules.

**Scoring contract:** Destination error, collisions, connectivity, order and resource/observation use separately; perturb whole flocks.

**Baselines:** Independent navigation, metric/topological/visible-neighbor policies as appropriate, and matched observation budgets.

**Scope cut:** No robots or learned vision; one geometric perturbation per comparison.

**Interpretation risk:** This tests the declared motion model, not language-agent competence. Hydrodynamics or oscillators require their own equations, not cosmetic arrows.

**Workload connection:** Direct to physical-swarm candidates’ source models; not offered as a common commercial LLM task.

<a id="flow"></a>
## FLOW — Move traffic through a bottleneck

**Scope:** Small

Simulated walkers, robots or job carriers pass through a crossing or narrow corridor under controlled arrival demand.

**Minimum fixture:** One corridor/intersection, a small particle or queue model, fixed routes and a controlled influx; use the candidate’s physical interaction law when required.

**Scoring contract:** Throughput, total waiting including outside queues, collisions/conflicts, discharge capacity and density.

**Baselines:** Uncontrolled flow; fixed signal; equal-demand geometry or policy controls.

**Scope cut:** One bottleneck and no city-scale simulator. Do not interpret a queue abstraction as measured crowd physics.

**Interpretation risk:** Changing arrivals, geometry and controller together makes capacity gains uninterpretable.

**Workload connection:** Direct computational scenario for crowd/traffic candidates; task-queue use is only an analogy if physical forces are essential.

<a id="osc"></a>
## OSC — Coordinate periodic polling of a shared service

**Scope:** Small

Workers choose phases for recurring polls or jobs; a separate physical variant uses the exact coupled-oscillator model.

**Minimum fixture:** A few dozen scheduled workers, one rate-limited mock endpoint, timing noise and explicit coupling; no live traffic.

**Scoring contract:** Queue peaks, deadline misses, useful throughput, phase order and energy/work proxies if defined by the model.

**Baselines:** Independent random phases, fixed staggering and synchronous polling.

**Scope cut:** Use deterministic timing simulation. Synchronization is not inherently beneficial; declare the task reward.

**Interpretation risk:** Endpoint polling preserves timing but not fluid or molecular coupling. Use a faithful oscillator simulation when that is the research claim.

**Workload connection:** Practical scheduling analogy for synchronization; not evidence of an existing deployed swarm product.

<a id="nca"></a>
## NCA — Test damage recovery in a local-state grid

**Scope:** Conditional

Run an existing small neural cellular automaton and perturb visible/hidden state or its update schedule.

**Minimum fixture:** A verified runnable checkpoint or trainable minimal published example, a small grid, fixed target or functional task and declared damage masks.

**Scoring contract:** Functional success and visible similarity separately; recovery time, recurrence and update cost under held-out damage.

**Baselines:** Undamaged run; visible-only and full-state lesions; original update scheduler.

**Scope cut:** Do not train a new reasoning NCA during the hackathon unless reproducibility is already established. Use a reproduction fallback and label it.

**Interpretation risk:** A hand-coded CA is not a trained NCA, and image regrowth alone does not answer semantic recovery questions.

**Workload connection:** Existing NCA brief and primary computational work in the biology review; runnable artifact availability remains a prerequisite.

<a id="opt"></a>
## OPT — Optimize a known black-box function

**Scope:** Small

Compare swarm search policies on simple functions with known optima, noise, rotations or controlled objective shifts.

**Minimum fixture:** Two or three declared objective families, seeded evaluations and a strict evaluation/communication ledger.

**Scoring contract:** Regret, evaluations to target, failure tails and overhead; use known optima without exposing them to policies.

**Baselines:** Random search, local search and the exact base optimizer with equal evaluations.

**Scope cut:** No expensive model training, broad benchmark leaderboard or changing objectives except the planned intervention.

**Interpretation risk:** Benchmark function gains do not establish better research agents. Preserve invariances and avoid tuning on test functions.

**Workload connection:** Direct optimization task for the OPT candidates; not an LLM-workload claim.

<a id="grid"></a>
## GRID — Coordinate a tiny cooperative delivery task

**Scope:** Conditional

Two or three agents exchange partial observations to collect and deliver objects on a small grid with explicit shared reward.

**Minimum fixture:** A small deterministic environment and already runnable baseline policies/checkpoints; varied partners or topology on held-out layouts.

**Scoring contract:** Task reward, collisions, rare failures, contribution value, communication cost and transfer gap.

**Baselines:** Independent policies, centralized-information ceiling and frozen-partner controls.

**Scope cut:** Avoid training a new MARL system from scratch. Fixed policies can test runtime robustness but not learning claims.

**Interpretation risk:** A scripted simulation does not establish emergent learning or credit assignment. Defer the learning claim without a runnable training baseline.

**Workload connection:** Existing MARL questions require an actual cooperative task; illustrative office workflows are insufficient for their learning claims.

<a id="replay"></a>
## REPLAY — Replay an agent workflow under controlled execution

**Scope:** Small

Execute the same bounded API or result workflow under altered schedulers, restart points, logging and observation interfaces.

**Minimum fixture:** Versioned fixture, complete event ledger, seeded randomness and explicit access permissions; engine or scheduler adapters only as needed.

**Scoring contract:** State equivalence, first divergent event, complete-run denominators, latency and invariant violations.

**Baselines:** Uninterrupted deterministic execution and full-observation evaluator kept outside agent context.

**Scope cut:** Reuse the existing offline harness and schema contracts; do not build a new general orchestration framework.

**Interpretation risk:** Replay verifies instrumentation. It does not show an LLM behavior effect without actual agents and a randomized comparison.

**Workload connection:** Directly supported by existing lab bookkeeping/replay tooling; new adapters still need implementation.

<a id="merge"></a>
## MERGE — Merge independently produced reports or state edits

**Scope:** Small

Workers return summaries, corrections or config proposals that are admitted into a parent’s bounded task state.

**Minimum fixture:** One structured state with explicit dependencies and permissions, several competing edits and deterministic validation; retain fork versions.

**Scoring contract:** Final task correctness, unauthorized changes, order dependence, stale reintroduction and retained useful information.

**Baselines:** Reject all changes, schema-only admission, full recomputation and fixed merge ordering.

**Scope cut:** Keep one merge operator fixed. Do not describe report merging as evidence about weight merging.

**Interpretation risk:** Combining individually acceptable reports can produce a bad joint state; isolation tests alone are insufficient.

**Workload connection:** Direct to report/memory fork-merge setups; model-parameter claims need WEIGHTS instead.

<a id="weights"></a>
## WEIGHTS — Merge small model updates on a known held-out task

**Scope:** Conditional

Combine already available tiny-model adapters or task vectors and test capability/safety interference.

**Minimum fixture:** Pinned checkpoints, compatible adapters, a validated merge implementation and independent evaluation data. All artifacts must be available before selection.

**Scoring contract:** Individual versus combined held-out performance, interaction effect and ordering sensitivity with equal adaptation data/compute.

**Baselines:** Base model, individual updates, exact standard merge and zero-update control.

**Scope cut:** Defer if checkpoint, licensing, compute or reproducibility setup is missing. A vector toy is only a mathematical illustration.

**Interpretation risk:** A memory-summary merge cannot test parameter interference, and a tiny-model result does not establish a production-model guarantee.

**Workload connection:** Direct computational requirement for parameter/learning candidates; no out-of-the-box readiness claim.
