# PC7 prospective development plan: verification under uncertain reliability

Status: offline development proposal; no native run admitted. Written before implementation, 2026-10-04. PC6 remains parked. The scope is to audit delivered native traces and build a decision-relevant baseline contract before deciding whether any model comparison is useful.

## TLDR
Would paying to verify a report become useful because it informs a later decision when reliability must be inferred from noisy finite calibration history? Build an exact two-report Bayesian controller and compare its development-fixture decisions to empirical-threshold and posterior-greedy controllers, with a separately labelled true-regime ceiling. No model performance claims or native calls. Stop native proposals if the exact controller already solves the specified application and no additional model role is identified.

## Question and prediction
PC5 supplied true calibrated reliability and required one action; its exact analytic controller dominates model use. PC7 removes known reliability and adds one future report. Hypothesis for instrument development: the value of revealed correctness can change a first verification decision relative to a myopic posterior threshold. This is analytically resolvable, so it is not itself a reason to query a model. The engineering choice is whether an exact finite-state controller is sufficient or a more complex empirical question is needed. Retain the exact controller if sufficient. A model successor requires an independently useful function such as interpreting unstructured evidence, grounded in an application corpus, not merely another supplied-number test.

## Setup
A hidden source regime H is good or bad. Conditional report correctness probabilities are .9 and .3. Prior P(good)=.5. Three calibration observations record correctness with known symmetric bit-flip noise eta in {.1,.3}. After calibration, the regime switches with known probability s in {0,.4}, once; it then remains fixed for two decisions. Three observed bits and metadata are actor-visible; H, latent calibration correctness, current/future correctness draws and posterior/answer tables are evaluator-only. Verification reveals actual correctness noiselessly at cost c in {.1,.4}; trusting incurs loss1 on a wrong report and0 otherwise, with no feedback. Verification makes the current report correct, plus cost c, and permits learning for the remaining report. Both policies pay the same costs and have the same information eligibility. No swarm or peer-message effect is claimed.

Controls: empirical observed-accuracy threshold (explicitly naive under noisy/shifted histories); corrected Bayesian posterior-greedy; exact two-step Bellman value-of-information; true-regime oracle with no future outcome access; always-check/trust. Trace state, posterior and all candidate action values belong in evaluator telemetry; native actors, if ever used, would receive only eligible observations and the declared stochastic contract. Each controller owns its own history after decisions; common exogenous world draws do not mean sharing counterfactual discoveries.
