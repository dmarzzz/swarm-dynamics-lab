# O1: outage-response prototype and bounded competence diagnostic

Prospective plan, written before implementation,2026-10-04. Owner directed building/validating this small outage prototype, executing a bounded ready scope and the existing Q-A7 diagnostic. One cumulative USD20 study ledger; no reset. This is a controlled operational emulator, not a production incident benchmark or optimal-size result. [Design rationale](../design-refresh-2026-10-04/README.md), [prior scientific post-mortem](../reviews/q-a6-post.md), [Q-A7 hold](../reviews/q-a7-route-assessment.md).

## TLDR

Build four synthetic operational scenario mechanisms with stable/changing variants: endpoint failover, dependent-service rerouting, protocol rotation and shared capacity reduction. Compare a tool-capable single model context, fixed four-context team, deterministic public-state controller and four-to-one contraction. Validate all worlds and checker faults offline. Native O1 begins with four single-agent competence episodes; only if at least3/4 succeed without invariant violations run an eight-episode development demonstration on one root ×two variants ×four arms. No automatic larger study. Q-A7 remains a separate existing diagnostic after O1, only if the shared admitted route has not failed. All native stages require ordinary public/source/credential/account/ledger admission.

## Question and prediction

Can this instrument expose a useful difference between parallel diagnosis and coupled repair without giving a weak single agent or an unsafe fixed team? Prediction is deliberately conditional: contraction may reduce stale/duplicate repair work, but a safe deterministic controller or competent single agent may match it. The first decision is instrument/competence readiness, not efficacy. If the scripted controller solves the support, this establishes a strong reference, not model value. If native N1 fails competence, stop the comparison; retain traces and revise offline before another scoped run.

## Setup

All roots are transparently authored development fixtures sharing one emulator. Four mechanism clusters are not a real-world sample; numeric/name variants are not independent roots. Native qualification uses four development variants. The optional eight-episode demonstration uses a distinct generated instance from one template and is descriptive only, not untouched population validation. No statistical significance, optimal-N or non-inferiority claim.

A world has versioned service configurations and a public dependency/endpoint directory, health telemetry and a shared resource cap. Four configured services need repair and monitoring through an eight-tick window. Initial observations contain service names, health symptoms and legal tools; inspect actions retrieve current source-of-truth state, never future event tape, hidden target, scorer output or solution. Observations are read at one tick and writes take effect on the next; Tick2 applies an exogenous update before queued actions in changing variants; stable variants preserve the state. The event schedule is fixed independent of actor performance. Correct early work must remain correct through the window. No paid model result affects the event tape.

Actors may inspect public state, apply conditional service patches or wait. Writes require both service and directory versions and reject stale attempts. All arms use the same checks; invalid/unsafe committed state is retained for scoring. S gets up to4 tool actions in one response, F and C get one action per active actor up to4 total per tick. Coordinator counts among the four and may perform work. F/C receive identical observations/roster/checkpoint structure before contraction. C retires workers after at least two stale-version rejections in its last four write attempts; in-flight turns drain first, with no re-expansion. D is a public-state rule controller: same observations/actions/capacity, no evaluator import, no model calls. It is explicitly a strong simple baseline, not an LLM team with hidden free reasoning.

Contexts persist only within episodes using a fixed rolling memory: system instruction, the immediately preceding user/assistant turn, and the current public board. Raw full histories remain in traces but are not all resent. This identical rule bounds context in every model arm; no evaluator summary or free model summarizer. Common public board includes prior action receipts. Four model calls can run in parallel in a round, but request and tool concurrency are reported separately. Model inference wall time is measured; emulator ticks are a controlled action clock, not physical seconds or proof of production speedup. No hidden time conversion.

## Metrics

Full success: every required service predicate holds at the end of the monitoring window and no critical invariant violation was committed. Secondary: service health fraction over ticks, final predicate fraction, accepted/stale/rejected writes, unnecessary/duplicate repairs, actual context count, model/tool concurrency, tick-to-recovery, measured wall time, tokens, settled and unresolved cost. Keep endpoint/protocol/capacity failure categories separate. All admitted assignments appear in reconciliation; unstarted is not wrong. Provider failure is operational missingness, not inability to diagnose an outage.

Per-arm effects are descriptive paired observations. No hypothesis support threshold or confidence claim from the one-root demonstration. Qualification3/4 is a development gate, not evidence of reliability. If D dominates all model policies, recommend the rule controller for this declared support and broaden realism offline only if there is a concrete residual need.
