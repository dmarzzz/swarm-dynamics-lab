# Scale the question; keep the claim tied to evidence

Use this short table within the existing setup/next-run record when scale or presentation matters. Link existing answers rather than duplicating them. It refines [case quality](TEST-CASE-QUALITY.md), [run quality](RUN-QUALITY.md) and [visualization](RUN-VISUALIZATION.md); it creates no new service, approval or universal sample floor.

## Before increasing the swarm

| Record | Minimum useful answer |
|---|---|
| Why scale? | Which mechanism changes: communication bottleneck, evidence coverage, congestion, division of labor, correlated errors or inheritance depth? State what a null/adverse result would change. A larger demo alone is not a scientific justification. |
| What does N mean? | Native decision makers, programmed identities, independent teams, generations and rounds are separate counts. Name the sampled root and nested observations. Concurrent agents and total identities over a run are different. |
| What stays fixed? | Unique evidence, attacker resources, check/tool budget, context per role, communication degree/bandwidth, horizon and compute. Explain intentional changes; equal tool slots need not mean equal model cost. |
| Which comparison? | Strong singleton or simple controller with the same permitted information; no-interaction/resampling control for social claims; same-model arms for a pure N effect. If model and N both change, claim configuration performance. |
| Is the task informative? | Worked correct, wrong, insufficient-evidence/abstain and invalid-output cases; treatment-sensitive and invariant controls; attainable target calculations. Separate task readiness, native qualification and admission. |
| What is sampled? | Independent roots/episodes, pairing and shared sources; development versus untouched evaluation. Choose counts for precision or a candid finite diagnostic. Many actors on one world cannot buy generality. |
| Is context controlled? | Pin model/route, prompt/tools/schema, role-visible information, memory initialization/update/reset, graph and scheduler. Record actual effective inputs and truncation; seeded startup does not guarantee identical hosted answers. |
| What will stop it? | Existing qualification, futility/failure, time and spending limits; minimum useful contrast. Forecast expected use and enforce worst-case reservations, including prior uncertainty and infrastructure. No new allowance from a new stage. |

## A reusable result caption

**Claim:** [narrow supported statement]. **Scope:** [native/scripted/replay; model/configuration; independent roots and nested actors/calls]. **Outcome:** [numerator/denominator per arm, missing/unstarted, paired uncertainty or descriptive limit]. **Boundary:** [largest unresolved confound or failed gate]. **Evidence:** [attempt, source and scored artifact].

Use actual observed outcomes. Label fixtures, simulations, animations, extrapolations and proposed stages. A film can explain the mechanism without establishing its efficacy. Show the latest decision-relevant adverse evidence alongside an older successful demonstration; separate interface, capability, scientific interpretation and process status.

## Portfolio decisions

| Decision | Evidence that belongs in it |
|---|---|
| Scientific priority | Unresolved useful question, informative contrast, evidence gap, feasible next test and expected decision value |
| Evidence confidence | Existing [confidence metadata](../../EVIDENCE-METADATA.md), current sampled units and limitations; never visual quality or commit count |
| Presentation order | Clarity, verified visuals and audience fit; explicitly editorial, with honest captions |
| Dispatch | Applicable authority plus current study-specific admission; neither rank nor a polished chart grants permission |

The [top-10 review integration](../../studies/vishesh/top10-integration-2026-10-04/README.md) illustrates the distinctions. Reuse strong controls from neighboring studies, but preserve their ownership, model/task limits and immutable results. Generalize their method only after checking that its information and resource assumptions fit the new question.
