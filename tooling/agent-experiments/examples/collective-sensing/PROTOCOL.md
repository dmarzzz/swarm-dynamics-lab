# Worked example: independent evidence versus repeated messages

Status: **finished illustrative protocol and runnable scripted demonstration; not a registered or executed LLM study**. This illustrates evidence aggregation without selecting a team project. It can be adapted to distributed diagnosis, research evidence aggregation, incident triage or resource allocation with an objective truth label.

## Question and claim boundary

Does explicit source-provenance handling improve final decision accuracy when five agents receive partially informative observations and some observations are repeated in peer messages?

Primary estimand for a prospective LLM study: the mean difference in the fraction of agents correct at the decision deadline, between provenance-aware and ordinary decision instructions, averaged equally across sampled sensor-quality scenarios and fresh repetitions under the same model snapshot and resource cap. Whole swarm/world episodes receive the treatment. Agent decisions within an episode are dependent observations; their average is one run outcome.

The primary test concerns evidence aggregation under controlled message delivery. It does not establish autonomous social propagation, learned human preferences or validity as a human-population simulator. A future free-communication experiment would change the mechanism and require a new protocol.

## Scenario generator and study structure

Each scenario s has a sensor accuracy q_s sampled uniformly from [.55,.90]. For each independent repetition r, sample a fair binary truth and five observations independently correct with probability q_s conditional on truth. Each agent begins with its own observation. Across treatment conditions for the same (s,r), truth, observations and source IDs are identical. Across repetitions they are freshly generated; q_s persists as the scenario difficulty. The evaluator alone receives truth before scoring.

In the global delivery conditions, every agent receives all five source observations, with source 0 delivered three times and the other sources once. Every copy preserves the same original source ID. Thus there are seven messages representing five independent measurements. Duplication is generated by the harness, not by agents; no claim of spontaneous rumor emergence follows.

| Condition | Information and behavior | Role |
| --- | --- | --- |
| `naive_global` | Same seven source-tagged messages; scripted policy counts message values | Toy control only; deliberately transparent mechanism |
| `provenance_global` | Identical messages; scripted policy counts each source once | Toy primary treatment |
| `no_communication` | Own evidence only, including repeats if it is source 0 | Diagnostic baseline; different evidence reach |
| `provenance_ring` | Own and immediate two neighbors' evidence, deduplicated by source | Exploratory topology comparison; one-hop delivery |

The toy has one decision phase and no adaptive memory, tools or learned model. It preserves source identity exactly and uses deterministic majority; a tie uses the agent's own observation. With five distinct observations global provenance decisions cannot tie. Logical ordering does not permit agents to see one another's final decisions.

In a real LLM version, replace the deliberately naive scripted control with a **competent ordinary evidence-aggregation prompt**. Give both arms identical source metadata and tool access; add a narrowly specified provenance instruction only in treatment. Include a strong single-agent model receiving all unique evidence under the same aggregate cap, plus an independent-agent ensemble with a fixed aggregation rule. Compare the added instruction with other equally budgeted ways of spending the same effort. Do not describe the scripted naive baseline as a tuned LLM baseline.

## Prospective implementation details to freeze before model calls

After the lab survey and hypothesis review gates pass, copy the templates and resolve exact model snapshot, public prompts, task renderer, context and scorer hashes. All five instances share that model in the first study; model diversity is a later factorial experiment. Each sees the same baseline instructions across arms except the treatment sentence. Keep temperature, reasoning effort, output schema and context limits constant. Output a binary choice and optionally a calibrated confidence; do not require private reasoning traces. Protect hidden truth and source snapshots outside agent write access.

For an initial controlled one-round LLM study, allocate a declared **system-wide** cap, for example 12,000 input and 3,000 output tokens total across five agents, with at most 512 output tokens per response and a 120-second whole-world deadline. These are candidate engineering limits, not validated cost/power recommendations. Confirm with a separate pilot that all arms fit; record actual input sizes, reasoning usage when exposed, dollars and time. Fix a price-aware dollar cap only after the exact provider is selected. The included template disables paid execution and sets its money cap to zero.

Avoid making the control prompt instruct agents to make a known error. Blind condition labels from graders. Deterministic correctness is the primary scorer; any LLM explanation grading is secondary and locally calibrated. Score invalid or absent final answers as incorrect for the deadline endpoint, but retain their failure class. Infrastructure failures have explicit retry limits and sensitivity bounds. Secret values are never part of a prompt, config, trace or example.

## Sampling and power: a worked planning calculation

Use a separate engineering pilot, such as 10 development scenarios × 4 repetitions, to inspect failure rates and variance. Do not use those data in the confirmatory set after tuning. This package has not collected that pilot.

Suppose a pilot supports a between-scenario SD of paired differences σ_b=.18 and a within-scenario SD σ_w=.20. These values are **assumptions for the example**, not measurements. For S=60 scenarios and R=4 paired repetitions:

```text
SE = sqrt(.18² / 60 + .20² / (60 × 4)) = .02658
95% normal CI half-width ≈ 1.96 × SE = .05210
For true difference δ=.08, two-sided α=.05: approximate power ≈ .853
Primary experiment: 60 × 4 × 2 = 480 swarm runs
With both exploratory diagnostic conditions: 60 × 4 × 4 = 960 swarm runs
With 5 agents each: 4,800 agent decisions, still only 60 scenario clusters
```

The normal planning approximation does not account for every feature of a bounded outcome or variance-component estimation. Simulate plausible scenario and failure distributions with the proposed final analysis before authorizing real compute. At the same 240 pairs, S=30/R=8 gives SE≈.0353 whereas S=120/R=2 gives SE≈.0209 under these assumed components. More scenarios improve precision here but may cost more to construct and validate. If only 20 scenarios exist, change the claim to that fixed set and quantify within-set repeat uncertainty.

For comparison, independent paired differences with SD=.25 require about 50 pairs for 80% power to detect .10, or 97 pairs for a .05 CI half-width. Those counts cannot be substituted for the nested design. The script recomputes both calculations, plus the nested calculation.

Agent count is fixed at five to make local-ring and global visibility distinct and allow majority decisions. To study scale, use a separately planned agent-count factor and hold aggregate resources or per-agent resources fixed according to the estimand. Increasing population size is not a substitute for new episodes.

## Allocation, analysis and stopping

Generate each paired world once logically using named seed streams, and instantiate a fresh copy per condition. Randomize execution order of conditions within (scenario, repetition); the script records that schedule. Across pairs use fresh environment draws. A live provider version would additionally balance order across time and provider capacity blocks.

Primary endpoint: correct individual decisions / 5 at the deadline, averaged equally by scenario after within-scenario pairing. Secondary endpoint: correctness of the majority group decision. Also report disagreement, source-use errors, failure rates, latency and total resource use in a real study. Define a source-use error by a prespecified rubric or intervention; an explanation mentioning a source alone does not prove causal reliance on it.

Compute D_sr = score(provenance_global) − score(control); average D_sr within each scenario, then across scenarios. A scenario-cluster bootstrap resamples the 60 scenario means, keeping all repetitions and treatment pairing. The toy uses 2,000 percentile-bootstrap resamples as an analysis illustration. For confirmation, validate coverage for the anticipated outcome distribution; consider a suitable hierarchical model or small-sample alternative. No bootstrap method fixes unrepresentative scenarios.

Prespecify one primary comparison; exploratory ring/no-communication comparisons are descriptive here. If promoted to co-primary, adjust the testing family and sample-size plan. Stop at the fixed allocation or a predeclared operational safety cap. Do not peek for significance. Report operational failures in assigned denominators and bound unavailable scores; do not delete troublesome worlds.

## Running and inspecting the demonstration

From the guide folder:

```sh
python3 scripts/toy_harness.py --config examples/collective-sensing/config.json --out ../../data/agent-study-demo
python3 scripts/validate.py
```

The harness writes a randomized planned ledger, resolved config, hash-chained events, run outcomes, a scenario-cluster summary, and input/output hashes. All messages are public synthetic values. Provider calls and charges are zero; local CPU time is not metered. Python runtime is recorded; exact byte reproducibility is checked within the installed runtime.

The validator checks identical starts across paired conditions, independent reset objects, known-answer provenance behavior, graph visibility, score reconstruction from event decisions, hash integrity, schema conformance, invalid config rejection and refusal to overwrite existing results. It runs the full 960-run demonstration twice and requires byte-identical files. It does not test real provider behavior, distributed scheduling, timeout recovery or a sandbox against hostile agent code.

## Interpretation and extensions

A difference between scripted policies illustrates a mathematical consequence of their rules. It is not an empirical discovery about LLMs. A real LLM result would support the effect of the tested provenance instruction in this controlled environment, within its confidence interval and model/task boundary. Null results with broad intervals are inconclusive; use equivalence margins to support negligible-effect claims.

Useful extensions include varying duplicate count while holding the underlying five observations fixed; corrupting provenance labels; varying q_s; adding correlated sensors; testing unequal source quality with a Bayesian oracle; allowing bounded multi-round agent-generated communication; testing frozen versus adaptive memory; and evaluating new model families. Each extension changes assumptions. Preserve test splits and distinguish preregistered interactions from exploratory findings.

For an external-influence study, replace binary sensors with fictional choices and a fixed independent utility rubric. Freeze profiling on a development split; compare neutral, generic framing and preference-informed framing on held-out agents and swarms. Choice shift and utility loss are different endpoints, and profiled-agent transfer does not establish recovered internal objectives. Reuse the same unit, pairing, budget and replication machinery.
