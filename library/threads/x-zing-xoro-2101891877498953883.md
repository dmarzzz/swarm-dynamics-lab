## Summary

Single-post explainer arguing that an "identity filter" for AI agents should answer only whether a request comes from an enrolled agent, and that the strong way to do this is to bind the agent's key to protected hardware (TPM, secure enclave) so the credential cannot be copied to another machine. The claimed consequence is that a leaked API key no longer equals a cloned agent, and mass Sybil creation then requires physical devices, raising its cost. No implementation, numbers or threat analysis are given; it is a conceptual framing, and it does not address one operator running many enrolled devices, which is the usual swarm case.

A useful way to think about identity filters for agents

they’re not API-key generators, response redactors, or cost trackers.
They answer one question:

> Is this request coming from the enrolled agent?”

The interesting part is how that identity is verified.

> The key is bound to hardware.

> TPM, secure enclave, or similar protected hardware stores the identity material.

> The key isn’t meant to be copied and reused elsewhere.

> Move the agent to another laptop → access stops.

That changes the security model.
Even if an API key leaks, copying the credential doesn’t automatically copy the agent’s identity.

A fake agent would need access to the enrolled physical device too.

That makes large-scale Sybil creation more expensive.

Important: identity filtering is just one layer. API management, response filtering, and usage accounting solve different problems.

The useful mental model:

agent identity ≠ username

agent identity ≠ API key

agent identity = hardware-bound enrollment

## Relevance to us

A clean statement of the "make identities cost hardware" defence for agent Sybil resistance: it prices each identity at one physical device rather than one API key. Useful as a baseline position when we discuss resource-based Sybil defences for agent swarms. Its gap is the interesting part for us: hardware binding prevents credential cloning, but does not stop a single operator from enrolling many devices or VMs with virtual TPMs, so it limits Sybil count only by hardware cost, the same economics as proof-of-work style defences. Practitioner opinion, no evidence.
