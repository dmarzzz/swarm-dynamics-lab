## Summary

Episode announcement for a Browserbase Navigate panel moderated by Allie Howe with Ian Livingstone (Keycard), Peyton Casper (Browserbase) and Ivy Lee (Visa). The motivating incident: a personal agent booking one Resy reservation made about 200 API calls per hour and got its user's account banned. From the transcript I read: Browserbase pushes enterprise customers to sign agent traffic with Cloudflare's Web Bot Auth so Cloudflare and reCAPTCHA can allow-list them; Visa's Trusted Agent Protocol has agents sign HTTP requests with a key resolved through a Visa agent registry, so merchants can tell a pre-onboarded payment-intent agent from a scraper; Keycard argues long-lived API keys make revocation impossible and permissions must be scoped per task ("optimize does not mean delete"). Panel opinion from vendors, no measurements beyond the Resy anecdote.

## Relevance to us

This is the industry's current answer to "which of the many agents hitting a site are legitimate": attach a verifiable operator identity to every request and let sites allow-list by registry. For swarm detection it inverts the problem (detect the signed good agents, treat the unsigned rest as suspect). For Sybil resistance the key gap is that a registry identity says who operates an agent, not how many agents that operator runs; one onboarded operator can still field a swarm, which is why the panel's rate and task-scope controls (the Resy 200 calls/hour case) matter as a second layer. Good framing source for the agent-identity section of a sybil-resistance survey; vendor perspective.
