## Summary

Author thread, verified (Gabriel Ilharco is first author). A task vector is the fine-tuned weights minus the pre-trained weights; these can be negated, added and combined by analogy, with no change to inference time and no need for the original data. Reported results: negating a task vector from GPT-2 fine-tuned on toxic data reduces toxic generations 6x; adding task vectors from two tasks to CLIP greatly improves zero-shot accuracy and almost matches separate specialised models; analogies (B+(A-C)) improve accuracy on a sentiment dataset. His outlook on cheap model control is stated as hope. Two later replies to others discuss the link to ensembles and weight averaging.

Task vectors offer a simple and efficient way of editing models. To create a task vector, we first fine-tune on a downstream task, then subtract the weights of the pre-trained model from the weights of the fine-tuned model. (3/n) https://t.co/zukfLFDbyy

And since all operations are element-wise, editing models with task vectors has no impact on inference time! (4/n)

## Relevance to us

Task arithmetic is the clean model of weight-space fork-and-merge: each fine-tuned child contributes a delta that is added back to the parent. It implies a corrupted child's delta (for example one trained on toxic data) merges in just as easily as a good one, and that negation can remove it if identified. See [[ilharco-2023-editing]] and [[hubinger-2024-sleeper]] on backdoors that survive training.
