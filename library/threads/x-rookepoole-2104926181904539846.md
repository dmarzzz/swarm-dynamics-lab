## Summary

Single long post proposing "Semantic Backtracking Injection": instead of poisoning the document a user query retrieves directly, the attacker plants a chain of semantic bridge documents that are unreachable from the original query and only become top-ranked after the agent's own follow-up queries drift toward them. The author reports preliminary numbers from a private harness called Venom: model-generated follow-up queries moved planted bridges 1.4 retrieval positions closer on average (closer in 83.3% of cases); a strict 2-hop chain (Q0 to X2, with X2 having zero retrieval eligibility from Q0 or Q1) completed in 8/8 controlled trials; a 3-hop chain also completed 8/8 at top-2 retrieval but only 12.5% at top-1. The post then argues the risk compounds under persistent memory because a low-trust bridge gets summarised, stored, and loses provenance, and proposes three invariants: model output cannot increase authority, retrieval distance cannot increase authority, transformation cannot erase taint. The numbers are the author's own, from an unpublished harness with 8 trials per condition; no code or paper is linked, so treat them as a claim, not a measurement we can check.

**1. @rookepoole, 2026-09-29 13:28 UTC, 148 likes** (status 2104926181904539846)

I think there is a new attack surface in AI agents that people are not really looking at yet.

Not the poisoned document. The path the agent takes to get there.

I’m calling it Semantic Backtracking Injection, or SBI.

Most RAG and memory poisoning work starts with the bad object. Malicious document goes in, retriever finds it, model reads it, behavior changes.

SBI gets weirder than that.

The malicious context does not even have to match what the user originally asked.

It can sit way off to the side, completely irrelevant to Q0, and only become reachable because the agent keeps generating new searches from the context it already found.

Something like:

User query → legitimate context → new retrieval query → semantic bridge → new query → another bridge → target context.

The important part is that the later nodes can be totally unreachable from the original request.

The model effectively teaches itself how to find them.

That is what I started measuring in Venom.

In one preliminary test, model-generated follow-up queries moved planted semantic bridges an average of 1.4 retrieval positions closer to activation. In 83.3% of cases, the bridge moved closer.

Then I wanted to know if it composed.

One hop is interesting.

Multi-hop is a much bigger problem.

So I built a strict 2-hop test:

Q0 → trusted context → Q1 → X1 → Q2 → X2

X2 had zero retrieval eligibility from Q0.

Zero from Q1.

It only became reachable after X1 changed what the model searched for next.

8/8 controlled trials completed the chain.

Then I pushed it again.

Q0 → A → Q1 → X1 → Q2 → X2 → Q3 → X3

This time X3 could not be retrieved from Q0, Q1, or Q2 at all.

Only X2 gave the model enough semantic information to generate the query that could reach X3.

Again, 8/8 controlled trials completed the chain at top-2 retrieval.

At top-1 retrieval, completion fell to 12.5%.

That is the part I keep staring at.

This is not just a poisoned-document problem anymore.

It looks more like:

SBI risk = semantic traversal × retrieval breadth × context sparsity × trust handling

The attack surface is not just what is in memory.

It is everything the agent can eventually make reachable from memory.

And persistent memory makes this even uglier.

Low-trust bridge → retrieved through SBI → summarized by the model → summary gets stored → provenance gets weaker or disappears → future retrieval starts from the derived state.

Now the original poisoned object might not even matter anymore.

The system carried it forward for you.

The rule I keep coming back to is:

Semantic relevance must never become authority.

I think the security model probably needs a few hard invariants:

MODEL OUTPUT CANNOT INCREASE AUTHORITY
RETRIEVAL DISTANCE CANNOT INCREASE AUTHORITY
TRANSFORMATION CANNOT ERASE TAINT
The core result from Venom so far is pretty simple:
Multi-hop semantic poisoning is a reproducible attack geometry.

I can place a downstream node where the original task cannot see it, the next retrieval cannot see it, and sometimes even the retrieval after that cannot see it.

Then the agent walks the semantic path and eventually makes that node the top-ranked result itself.

That changes the question for me.

I am not just asking:

“Can the model retrieve poisoned context?”

I am asking:

“What poisoned context can the model eventually teach itself how to retrieve?”

That is Semantic Backtracking Injection.

## Relevance to us

Directly on the fork-merge-security question of corruption on reintegration. The "summarised bridge gets stored and loses provenance" step is the same mechanism as a sub-agent returning a tainted summary that the parent merges into shared memory. The three invariants (output, retrieval distance and transformation cannot raise authority) are a candidate design rule for merge thresholds. The retrieval-breadth result (8/8 at top-2 versus 12.5% at top-1) is a concrete, cheap-to-replicate claim: narrower retrieval cuts multi-hop poisoning sharply. See [[gh-hackafterdark-phosphor]] for a runtime that implements taint-style rules (inferred content cannot self-promote) and [[x-mrjianglife-2104187840120881449]] and [[x-sarangmahatwo-2104918283086344578]] for the same "memory write is a trust transition" framing.
