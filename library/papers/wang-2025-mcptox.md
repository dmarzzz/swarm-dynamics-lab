## Summary

A benchmark for tool poisoning, where malicious instructions sit in a tool's metadata (its description) rather than in tool outputs. Built on 45 live MCP servers and 353 real tools, with 1,348 malicious test cases generated from three attack templates (explicit-trigger function hijacking, implicit-trigger function hijacking, parameter tampering) across 10 risk categories, evaluated on 20 LLM agent settings.

## Contribution

The first large-scale measurement of the attack class introduced informally in [[invariantlabs-2025-mcp]], showing it works without the poisoned tool ever being called.

## Key results

- Measured: many agents exceed 60% attack success; the highest is o1-mini at 72.8%.
- Measured: more capable models are often more susceptible, which the authors attribute to stronger instruction following.
- Measured: refusals are rare; the highest refusal rate (Claude-3.7-Sonnet) is under 3%.
- Measured: parameter tampering, which changes one argument of a legitimate call, is the most effective paradigm (average 46.7%), then explicit-trigger hijacking (36.7%), then implicit-trigger hijacking (26.7%).

## Methods and models

Real MCP server tool lists loaded into agent context alongside a poisoned tool description; test cases generated by few-shot prompting; success judged on whether the agent issues the attacker's intended tool call.

## Limitations and open questions

Single-turn evaluation; defences are not the focus; attack templates are fixed.

## Relevance to us

Q3. The most effective attack here does not change what the agent does, only one parameter of an otherwise correct action. That is the subtle form a corrupted returning part would favour: reports and actions that look right with one value altered. Output-level comparison across parts (Q2) catches it only if honest parts produce the same parameter. Also shows near-zero refusal: alignment does not treat a malicious instruction in trusted-looking metadata as suspicious.
